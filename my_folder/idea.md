# 뉴스 봐 — 아이디어 정리

| 항목 | 내용 |
|---|---|
| 문서 유형 | 아이디어 정리 메모 (기획서 작성 전 단계) |
| 버전 | v0.14 |
| 작성일 | 2026-10-12 |
| 작성방식 | 신규 (원본 메모를 정리 + 피드백 추가) |

---

## 1. 한 줄 요약

> **AI가 내가 흥미 있어 할 뉴스 여러 개를 하나로 묶고, "눌러보고 싶은 한 문장"으로 잠금화면/홈화면에 띄워주는 상식 뉴스 앱.**

---

## 2. 왜 필요한가 (문제)

상식을 늘리려고 뉴스를 보고 싶지만, 실제로는 **직접 찾아보지 않게 된다.** 찾아봐도 아래 문제 때문에 금방 그만둔다.

| # | 문제 | 설명 | 중요도 |
|---|---|---|:---:|
| P1 | **재미가 없다** | 관심 없는 기사가 먼저 보인다. "과학", "컴퓨터"처럼 분야를 정해도 범위가 너무 넓다. | ★★★ (가장 큼) |
| P2 | **내용이 부실하고 흩어져 있다** | 기사 하나만 보면 **내용이 적거나 결론이 없다.** 전체 그림을 보려면 여러 기사를 찾아 다녀야 한다. (제목이 자극적인 게 문제가 아니라, *정보의 양과 완결성*이 부족한 게 문제) | ★★★ |
| P3 | **깊이 들어가면 너무 어렵다** | 더 찾아보면 내 수준보다 지나치게 전문적인 글이 나온다. | ★★ |
| P4 | **찾아보는 행동 자체를 안 한다** | 검색하면 해결되지만, 귀찮아서 결국 안 하게 된다. | ★★★ |

**핵심 통찰**: 사용자가 뉴스를 *찾으러 가는* 구조로는 실패한다. 뉴스가 **먼저 찾아와야** 하고, 첫 문장이 **재미있어야** 한다.

---

## 3. 누구를 위한 서비스인가

- **1차 사용자**: 나 자신 — 상식이 부족하다고 느끼지만, 뉴스를 찾아보는 습관이 없는 사람
- **확장 대상(가정)**: 같은 고민을 가진 대학생·사회초년생
- 특징: 관심 분야(예: 컴퓨터)가 있지만 **전문가 수준은 아님**, 스몰토크(가벼운 대화)에서 뒤처지고 싶지 않음

---

## 4. 해결 아이디어 — 사용자 흐름

```
[1] AI가 뉴스를 모아 같은 사건끼리 묶음
        ↓
[2] 묶음마다 "흥미를 끄는 한 문장(후킹 문장)" 생성
        ↓
[3] 알림으로 자동 표시   ← 내가 찾아가지 않아도 보임 (원안: 잠금화면/홈화면)
        ↓
[4] 흥미가 생기면 클릭
        ↓
[5] 여러 기사를 합친 "기사 덩어리(종합 기사)" 보기
        ↓
[6] 각 내용 옆에 원본 기사 링크(출처) 표시
```

---

## 5. 핵심 기능

### 5-1. 페이지 구성 (3개)

| 페이지 | 내용 | 목적 |
|---|---|---|
| **오늘의 화제** | 지금 모두가 이야기하는 "뜨거운 감자". 스몰토크에서 무조건 알아야 하는 배경지식 | 상식 (관심 분야와 무관하게) |
| **나의 관심 분야** | 내가 직접 고른 분야(예: 컴퓨터) 뉴스 | 깊이 |
| **추천 뉴스** | 두 번째로 관심 있는 분야의 뉴스 (원안: AI가 "좋아할 것 같다"고 추정한 뉴스 → 6-7에서 변경) | 관심 범위 넓히기 |

### 5-2. 후킹 문장 (한 문장 미리보기)
- 여러 기사를 합쳐 **클릭하고 싶게 만드는 한 문장**을 AI가 생성
- 잠금화면/홈화면에 자동 노출

### 5-3. 기사 덩어리 (종합 기사)
- 같은 사건을 다룬 여러 기사를 하나로 합쳐 정리 → P2(부실·흩어짐) 해결
- 문장별로 **출처 기사 링크**를 단다

### 5-4. 신뢰도 분석
- AI가 기사의 **충실도·신뢰도**를 분석해 표시
- 아이디어: **기자 자체를 평가**하는 기능

### 5-5. 후킹 문장 만드는 전략 (원안)

| # | 방법 | 설명 |
|---|---|---|
| H1 | 제목 덕분에 클릭이 많은 기사 분석 | 기자 인지도·내용 인기도가 낮은데도 클릭이 많은 기사 = 제목의 힘. 그 제목들의 패턴을 학습 |
| H2 | "제목 어그로 전문 기자" 분석 | 항상 자극적으로 제목을 짓는 기자의 패턴 분석 |
| H3 | 극단적인 단어 사용 | "내일", "지금", "죽음", "멸망" 등 |
| H4 | 유행어·친근한 말투 | 너무 자극적이지 않은 선에서 |

## 6. 피드백 — 부족한 부분

중요한 것부터 정리했습니다.

### ✅ 6-1. 후킹 문장의 역할 — 결정됨

처음 피드백은 "자극적인 문장이 신뢰도와 충돌한다(클릭베이트를 따라 하는 것)"였으나, 아래 이유로 **충돌이 아니라고 정리**했습니다.

- P2의 "부실함"은 낚시성 제목이 아니라 **내용이 적거나 결론이 없는 것**을 말한다.
- 낚시성 제목이 나쁜 이유는 눌렀을 때 **뒤에 알맹이가 없기 때문**이다. 이 서비스는 눌렀을 때 **여러 기사를 모은 풍부한 종합 기사**가 나온다. 즉 어그로 기법을 쓰더라도 *약속한 것보다 더 많은 정보*를 준다.
- 따라서 **정보 제공(클리핑)이 본체, 어그로는 부가 기능**이다. 어그로 기자의 기법은 "사람을 끌어오는 기술"로만 빌려 쓴다.

**결정된 원칙**
| 우선순위 | 원칙 |
|:---:|---|
| 1 | 본체는 **여러 기사를 모아 풍부하고 결론까지 있는 정보**를 주는 것 |
| 2 | 후킹 문장은 사람을 끌어오는 **부가 기능** — 자극적인 표현·유행어 허용 |
| 3 | 후킹 문장의 **과장은 허용**한다. 대신 화면에 **안내 문구**를 둔다 |

**과장을 허용하는 이유**
- 관심을 끌려면 과장이나 약간의 혼동을 완전히 피할 수 없다.
- 지금 기사 제목도 "멸망", "임박" 같은 과장 표현을 쓰지만, 제목만 보고 그대로 믿는 사람은 거의 없다. 책 제목 「공부하지 않아도 되는 이유」를 보고 공부를 그만두는 사람이 없는 것과 같다.
- 사용자는 후킹 문장을 "사실"이 아니라 "**미끼**"로 받아들인다. 문장만 보고 넘기는 경우까지 책임지도록 설계하지 않는다.

**안내 문구 (예시)**
> "오늘의 한 문장"은 흥미를 위해 사실을 과장할 수 있어요. 정확한 내용은 꼭 기사 본문에서 확인해 주세요.

### ✅ 6-2. 잠금화면 표시는 기술적으로 제한이 크다 — 결정됨

- **아이폰(iOS)**: 잠금화면에 앱이 마음대로 화면을 띄울 수 없습니다. 작은 **잠금화면 위젯**(글자 수 매우 적음)이나 **알림**만 가능합니다.
- **안드로이드**: 잠금화면 앱/위젯이 비교적 자유롭지만 기기·버전마다 다르고, 배터리 정책 때문에 자동 갱신이 막히기도 합니다.

**결정**: MVP(최소 기능 제품)는 **알림만** 사용한다 (하루 1~3회). 홈화면 위젯은 뺀다. ✅ (v0.10에서 위젯 제외)

**플랫폼**: **안드로이드**로 결정 ✅ (아래 비교 근거)

| 플랫폼 | 위젯 | 알림 | 개발 환경 | 비용 | 구현 난이도 |
|---|---|---|---|---|:---:|
| **안드로이드** | 자유로움 | 쉬움 | Windows에서 개발 가능 | 무료 (설치 파일로 바로 설치) | **쉬움** |
| 아이폰 | 가능 (전용 언어 Swift 필요) | 쉬움 | **Mac 필수** | 연 약 13만 원 (애플 개발자 계정, 없으면 7일마다 재설치) | 어려움 |
| 컴퓨터 (웹) | 사실상 불가 | 브라우저 알림 가능 | 어디서나 | 무료 | 쉬움 — 단 위젯 목표를 못 이룸 |

- 핵심 원칙: **AI 작업(뉴스 수집·묶기·요약·문장 생성)은 서버에서** 하고, 앱은 결과를 보여주기만 한다. 그러면 나중에 아이폰·웹을 추가할 때 화면만 새로 만들면 된다.

### ✅ 6-3. 뉴스 데이터를 어디서, 어떻게 가져올지 없다 — 결정됨

- 언론사 기사 본문은 **저작권**이 있습니다. 본문을 마음대로 긁어와(크롤링) 합쳐서 보여주면 법적 문제가 될 수 있습니다.
- 사용할 수 있는 길: 네이버 검색 API(제목·요약·링크 제공), 빅카인즈(한국언론진흥재단 뉴스 데이터), 언론사 RSS 등. 각각 **제공 범위·이용 조건**을 확인해야 합니다.
- 기사 덩어리는 "본문 복사"가 아니라 **AI가 새로 쓴 요약 + 원문 링크** 형태가 안전합니다.

**조사 결과 (2026-10-12)**

| 출처 | 가입·키 | 주는 것 | 본문 | 특징 | 쉬움 |
|---|---|---|:---:|---|:---:|
| **구글 뉴스 RSS** | 필요 없음 | 제목, 링크, 언론사, 날짜 | ✕ | "주요 뉴스" 피드는 **같은 사건을 다룬 다른 언론사 기사 목록이 이미 묶여서** 옴. 분야별(기술 등)·검색어별 피드도 있음 | ★★★ |
| **네이버 뉴스 검색 API** | 무료 가입 후 키 발급 | 제목, 요약 몇 줄, **원문 링크**, 날짜 | ✕ (요약만) | 하루 25,000회 무료. 검색어 기반 (인기 뉴스 목록 기능은 없음) | ★★★ |
| 빅카인즈 | 기관·공모 위주 | 분석 기능 | 불확실 | 개인·학생 API 신청 가능 여부가 확인되지 않음 | ★ |

- 세 출처 모두 **본문 전체는 주지 않는다.** 본문이 필요하면 원문 링크를 열어 **본문 추출 라이브러리**(예: 파이썬 `trafilatura`)로 글자만 뽑아야 한다.
- 구글 뉴스 링크는 구글을 한 번 거치는 주소라 원문 주소를 바로 알기 어렵다. 네이버는 원문 링크를 바로 준다.

**결정된 조합 ✅ (과제용, 가장 쉬운 방법)**

| 페이지 | 출처 | 이유 |
|---|---|---|
| 오늘의 화제 | 구글 뉴스 "주요 뉴스" RSS | 지금 뜨는 사건 + 관련 기사 묶음을 **구글이 대신 해줌** → 기사 묶기 작업을 크게 줄임 |
| 나의 관심 분야 / 추천 | 네이버 뉴스 검색 API (관심 키워드로 검색) | 키워드 검색이 쉽고 원문 링크를 바로 줌 |
| 종합 기사 본문 | 원문 링크 → 본문 추출 라이브러리 | 실패하면 요약(description)만으로 작성 |

- 저작권: 대학 과제·비공개 시연 범위에서는 부담이 적지만, **앱을 공개 배포하지는 않는다.** 화면에는 항상 출처 링크를 단다.

### ✅ 6-4. 후킹 전략 H1·H2에 필요한 데이터가 없을 가능성이 높다 — 결정됨

- 문제: 포털·언론사는 **기사별 클릭수**를 공개하지 않는다. "기자 인지도", "내용 인기도"를 숫자로 잴 방법도 없다.
- **결정**: H1(클릭수 분석)·H2(어그로 기자 분석)는 뺀다. 대신 **AI에게 문장 규칙 + 예시를 주는 방식**으로 만든다.
  - 규칙: H3(극단적인 단어) + H4(유행어·친근한 말투)
  - 예시: 자극적인 기사 제목 10~20개를 지시문에 함께 넣는다
- (선택, 시간이 남으면) 같은 뉴스에 문장 2개를 번갈아 보여주고 더 많이 눌린 쪽을 고르는 실험(A/B 테스트)

### ✅ 6-5. 기자 평가는 명예훼손 위험이 있다 — 결정됨

- 문제: 실명 기자에게 "어그로 기자" 같은 평가를 붙이면 명예훼손·분쟁 위험이 있다.
- **결정**: **기자 평가 기능은 없앤다.** ✅
- ⏳ 확인 필요 (추천안): 대신 **"이 소식을 보도한 언론사 수"**를 보여줄지. 예) 📰 7개 언론사 보도 — 구글 뉴스가 관련 기사를 이미 묶어 주므로 숫자만 세면 된다.

### ✅ 6-6. 문제 P3(너무 어렵다)에 대한 해결책이 빠져 있다 — 결정됨

- **결정**: 종합 기사 안의 **어려운 단어에 밑줄**을 긋고, **탭(터치)하면 해설**이 뜬다. (원안은 마우스 올리기였으나 폰에 맞게 변경)

### ✅ 6-7. 개인화(맞춤 추천) 방식이 정해지지 않았다 — 결정됨

- **결정**: 앱을 처음 시작할 때 관심 분야를 **단계별로** 고른다.

```
① 가장 좋아하는 큰 분야 고르기   (예: 자연, 경제, 과학 …)
        ↓
② 그 분야 안에서 깊은 분야 고르기 (예: 과학 → 우주)
        ↓
③ 두 번째로 관심 있는 큰 분야 고르기 (깊은 분야는 고르지 않음)
```

**고른 분야와 페이지의 연결**

| 페이지 | 채우는 기준 |
|---|---|
| 오늘의 화제 | 그때그때의 **시사**. 모르면 "조금 무식하다" 소리를 들을 수 있고, 직장 등에서 스몰토크에 낄 수 있을 정도의 뉴스 (이 앱은 상식을 넓히고 싶은 사람을 위한 앱) |
| 나의 관심 분야 | ①② 가장 좋아하는 분야 + 그 안의 깊은 분야 |
| 추천 뉴스 | ③ 두 번째로 관심 있는 분야 |

### ✅ 6-8. AI가 사실을 지어낼 위험 (환각) — 결정됨

- **결정**: **아직 생기지 않은 문제는 미리 막지 않는다.** MVP에서는 별도 대책 없이, 원래 아이디어대로 출처 기사 링크만 단다. 실제로 문제가 생기면 그때 대응한다.

- **결정**: 종합 기사의 **문단마다 출처 번호 [1][2]**를 달게 하고, 맨 아래에 기사 링크 목록을 둔다.
- 별도 검증 단계는 두지 않는다 (지시문으로만 처리).

</details>

### ⏳ 6-9. 그 밖에 정해야 할 것 — 보류 (아래는 추천안, 미확정)

| 항목 | 결정 |
|---|---|
| 성공 기준 | ① 시연: 위젯 문장 → 클릭 → 종합 기사 + 출처까지 끝까지 동작 ② 본인이 2주 사용하며 클릭 기록 남기기 |
| 업데이트 주기 | 하루 3번(아침·점심·저녁) 뉴스 수집·문장 생성, 알림도 3번 |
| 서버 | 서버를 직접 운영하지 않는다. **파이썬 스크립트**가 정해진 시간에 돌아 결과를 **Firebase**(구글의 무료 앱 데이터 저장 서비스)에 올리고, 앱은 읽기만 한다 |
| AI 비용 | 작은 AI 모델 사용 → 과제 규모에선 부담이 적을 것으로 예상. 사용할 AI를 정할 때 계산 |
| 경쟁 서비스와 차이 | 8장 유지: "내 취향의 사건 하나를, 여러 기사로 모아, 내 수준으로" |
| 이름 | ✅ **뉴스 봐** |

---

## 7. 이 아이디어의 강점

- **문제 정의가 솔직하고 구체적**입니다. "찾아보게 되지 않는다", "재미없는 기사가 먼저 보인다"는 실제로 많은 사람이 공감하는 문제입니다.
- **"찾아가지 않아도 먼저 보여준다"(푸시형)** 구조가 문제 P4를 정확히 겨냥합니다.
- **여러 기사를 한 덩어리로 묶는 것**은 기존 포털과 확실히 다른 차별점입니다.
- **'오늘의 화제' 페이지**로 관심 분야 편식을 막으려는 설계가 좋습니다.

---

## 8. 차별점 정리 (한 문장)

> 포털은 "기사 목록"을 주고, 요약 뉴스레터는 "남이 고른 뉴스"를 준다.
> 이 서비스는 **"내 취향에 맞춘 사건 하나를, 여러 기사로 모아, 내 수준으로" 준다.**

---

## 9. MVP(최소 기능 제품) 범위 — 결정됨 ✅

**원칙**: 초기에는 기능을 **최대한 적게** 한다.

**확인할 가설**: "흥미로운 한 문장을 먼저 보여주면, 사람들이 뉴스를 실제로 눌러 읽는다."

### MVP 기능 (4개)

| # | 기능 | 관련 결정 |
|:---:|---|---|
| F1 | **카테고리별 사용자 맞춤 기사 모으기** — 카테고리 = 오늘의 화제 / 나의 관심 분야 / 추천 뉴스 (5-1의 3개 페이지) | 5-1, 6-3 (구글 뉴스 RSS + 네이버 뉴스 API) |
| F2 | **여러 기사를 한 기사로 정리** — 정보를 풍부하게, 어려운 단어 해설 포함 | 5-3, 6-6 |
| F3 | **기사를 토대로 어그로 한 줄 만들기** | 6-1 (과장 허용 + 안내 문구), 6-4 (규칙 + 예시 지시문) |
| F4 | **사용자에게 알림 보내기** — 알림에 어그로 한 줄 표시 (위젯 없음) | 6-2 (안드로이드) |

### MVP에서 뺀 것 (나중에)

| 기능 | 비고 |
|---|---|
| 기자 평가 | 6-5에서 삭제 결정 |
| AI 신뢰도 분석 / 보도 언론사 수 표시 | 5-4 |
| 클릭수 기반 제목 분석, 후킹 문장 A/B 테스트 | 6-4 |
| 잠금화면 전용 화면, 홈화면 위젯 | 6-2 |
| 다중 사용자·회원 기능 | |

## 부록. 원본 메모

> 뉴스 클리핑하는 프로그램?? (잠금화면에 나오도록)
>
> 상식이 부족한거같아서 뉴스를 보고싶은데 직접 찾아보게되지 않고, 찾아봐도
> 1 내 관심분야가 아니거나 (과학 분야라 해도 너무 다양하고 컴퓨터 분야라 해도 너무 다양하고...)
> 2 내용이 부실하거나 퍼져있고 (이게 큼)
> 3 좀 더 자세히 찾아보면 내 수준에 지나치게 전문적이라서 어렵다
>
> 물론 검색을 더 하거나 하면 해결되겠지만 직접 안하게됨. 일단 재미없는 기사를 보게되는게 젤 큰듯
>
> AI가 내가 흥미를 가질법한 흥미로운 기사들을 합쳐서 흥미를 끄는 한 문장을 만들도록 하고싶다
>
> 그리고 그걸 홈화면에 자동으로 띄어주고 내가 그거에 흥미를 느끼면 클릭해서 들어가서 여러 기사들을 합친 기사덩어리같은걸 보여주고... 그 내용 출처를 기사 링크로 달아두고....
>
> 그리고 상식에 대한 고민인 만큼 관심분야만이 아니라 큰 사건도 알려주면 좋겟다
>
> 페이지를 나눠서
> - 오늘의 화제 거리 페이지 (완전히 뜨거운 감자 그냥 스몰토크로 무조건 있어야하는 배경지식같은거)
> - 나의 관심분야 페이지 (컴퓨터쪽)
> - 내가 좋아할걸로 추정되는 뉴스
>
> AI가 충실도? 신뢰도를 분석. 기자 자체를 평가해줘도 좋을거같음
>
> AI가 어떻게 섹시한 문장을 만들어 낼 수 있을까?
> 1 기사 제목때문에 클릭수가 많은 기사들(기자의 인지도가 없거나, 내용의 인기도가 낮거나, 내용이 보이지 않는데도 클릭수가 높은 기사)의 제목을 분석
> 2 기자들중에 제목 어그로 전문 기자(기사 제목을 항상 자극적으로 짓는 기자)가 있을거같은데 그 사람을 분석
> 3 "내일", "지금", "죽음", "멸망" 같은 극단적인 단어 사용
> 4 너무 자극적이지 않다면 유행어도 사용 친근감 드는 말투 사용
