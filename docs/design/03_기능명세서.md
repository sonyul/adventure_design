> **이 문서를 읽는 법**
> - 이 문서는 [기획서](02_기획서.md)의 기능 4개(FR-01~FR-04)를 **"무엇을 받아서, 어떻게 처리하고, 무엇을 내보내는지"** 수준으로 자세히 풀어 쓴 문서입니다.
> - **✅ 확정** = 기획서에 ✅로 정해진 내용(또는 그것을 그대로 옮긴 것)입니다.
> - **✅ 확정** 중 기획서에 없던 세부 값은 작성자가 제안하고 **사용자가 확인해 확정**한 것입니다 (v1.1 개별 결정 4건, v1.2 나머지 전부 제안대로 확정). 어떤 값이 새로 추가된 것인지는 [10장](#10-확인이-필요한-제안-항목-모음)·[11장](#11-기획서에-없던-내용-중-이-문서에서-새로-추가한-것)에 남겨 두었습니다.
> - **⏳** = 이 문서가 아니라 뒤 문서(06 데이터 모델, 08 아키텍처, 09 보안)에서 정할 항목입니다.
> - 상태 기호: ✅ 완료(확정) · ⚠ 부분 · 🔴 미작성 · ⏳ 진행 / 제안(확인 필요)
>
> **약어 풀이**
> - **FR**(Functional Requirement, 기능 요구): 시스템이 해야 하는 기능. 이 문서에서는 FR-01-1처럼 기능 아래 세부 요구에도 번호를 붙입니다.
> - **NFR**(Non-Functional Requirement, 비기능 요구): 기능 자체가 아니라 "얼마나 빠르게·안정적으로·안전하게" 동작해야 하는지에 대한 요구
> - **SLO**(Service Level Objective, 서비스 목표 수준): "알림이 10번 중 9번 이상 제때 와야 한다"처럼 숫자로 정한 목표
> - **API**(Application Programming Interface, 프로그램 간 통신 규격): 다른 서비스의 데이터를 정해진 방식으로 받아오는 창구
> - **RSS**(Really Simple Syndication): 웹사이트가 새 글 목록을 정해진 형식으로 내보내는 방식
> - **AI**(Artificial Intelligence, 인공지능): 이 문서에서는 글을 읽고 새로 써 주는 언어 모델(구글 Gemini)을 말합니다.
> - **JSON**(JavaScript Object Notation): 컴퓨터끼리 데이터를 주고받을 때 쓰는 "이름: 값" 형태의 글자 형식
> - **KST**(Korea Standard Time, 한국 표준시)
> - **MVP**(Minimum Viable Product, 최소 기능 제품): 가설을 확인할 수 있는 가장 작은 첫 버전

### 1-3. 클릭 기록이 필요한가? (판단)

- 기획서 6장 성공 기준 ✅ ②는 **"본인이 2주 사용하며 클릭 기록 남기기"** 입니다.
- 기획서 1-4의 확인할 가설은 **"흥미로운 한 문장을 먼저 보여주면, 사람들이 뉴스를 실제로 눌러 읽는다"** 입니다.
- 손으로 적는 방법도 있지만, 2주 동안 하루 3번(총 42번) 알림의 "봤다/눌렀다"를 빠짐없이 적기는 어렵고, 가설을 확인하려면 **알림이 몇 번 떴고 그중 몇 번 눌렀는지**를 숫자로 알아야 합니다.
- 작성자 제안: 클릭 기록 기능(FR-04-4)을 넣자.
- **결정 ✅ (사용자, v1.1)**: 클릭 기록 기능은 **넣지 않는다.** 기능을 최소로 유지한다.
- 따라서 성공 기준 ②의 클릭 기록은 앱 기능이 아니라 **사용자가 직접(메모 등) 남긴다.**

## 3. 기능 상세 — FR-01 카테고리별 사용자 맞춤 기사 모으기

### FR-01-1 처음 시작 시 단계별 분야 선택

| 구분 | 내용 |
|---|---|
| 입력 | 사용자가 앱을 처음 실행했을 때의 화면 선택 |
| 처리 | 아래 순서로 3단계 선택을 받는다 (✅).<br>① 가장 좋아하는 **큰 분야** 1개 (10개 중)<br>② ①의 큰 분야 안에서 **깊은 분야** 1개 (4~6개 중)<br>③ 두 번째로 관심 있는 **큰 분야** 1개 (깊은 분야는 고르지 않음)<br>- ✅ 확정: 각 단계에서 **1개만** 고른다 (여러 개 고르기 없음).<br>- ✅ 확정: ③에서는 ①에서 고른 큰 분야를 **고를 수 없게** 흐리게 표시한다 (같은 분야 중복 방지).<br>- ✅ 확정: 이전 단계로 돌아가는 "이전" 버튼을 둔다. |
| 출력 | 선택 결과 3개(1순위 큰 분야, 깊은 분야, 2순위 큰 분야) → FR-01-2로 저장 |
| 예외 | - ✅ 확정: 고르지 않고 앱을 닫으면 저장하지 않고, 다음 실행 때 처음 선택 화면을 다시 보여준다.<br>- ✅ 확정: 분야를 고르기 전이라도 "오늘의 화제" 페이지는 관심 분야와 무관하므로 볼 수 있다. |
| 완료 기준 | - 처음 실행 시 ①→②→③ 순서로 선택 화면이 나온다.<br>- ②에는 ①에서 고른 큰 분야의 깊은 분야만 나온다 (예: 과학 → 우주·생명과학·물리·화학·로봇·공학·에너지).<br>- ③ 완료 후 다시 앱을 열면 선택 화면이 나오지 않는다. |

**분야 목록 ✅** — 기획서 3-1 "분야 목록" 표(큰 분야 10개, 깊은 분야와 검색 키워드)를 **그대로** 씁니다. 이 문서에 다시 옮겨 적지 않습니다(한 곳에서만 관리). 키워드는 시작용 초안이며 검색 결과가 엉뚱하면 고칩니다 (✅).

### FR-01-2 선택한 분야 저장

| 구분 | 내용 |
|---|---|
| 입력 | FR-01-1의 선택 결과 3개 |
| 처리 | 앱이 Firestore에 저장한다 (✅). 파이썬 스크립트는 실행할 때마다 이 값을 읽어 **고른 분야만** 처리한다 (✅, AI 비용 절약). |
| 출력 | Firestore의 "사용자 설정" 문서 1개 (⏳ 저장 위치·이름은 [데이터 모델](06_데이터모델_ERD.md)에서 정함) |
| 예외 | - ✅ 확정: 저장할 때 인터넷이 끊겨 있으면 "저장하지 못했어요. 인터넷 연결 후 다시 시도해 주세요" 안내 후 다시 시도 버튼을 보여준다.<br>- ✅ 확정: 스크립트가 실행됐는데 저장된 분야가 없으면 **오늘의 화제만** 처리하고 나머지 두 페이지는 건너뛴다. |
| 완료 기준 | - 선택 직후 Firestore 콘솔(관리 화면)에서 3개 값이 보인다.<br>- 다음 예약 실행에서 스크립트가 그 분야의 키워드로만 검색한다 (실행 기록으로 확인). |

### FR-01-3 하루 3번 예약 실행

| 구분 | 내용 |
|---|---|
| 입력 | 시각 (KST) |
| 처리 | GitHub Actions 예약 실행으로 **6:30 · 11:30 · 18:30**에 파이썬 스크립트를 실행한다 (✅). 예약 실행은 몇 분씩 늦어질 수 있어 알림 30분 전에 돌린다 (✅).<br>- 참고: GitHub Actions 예약 시각은 세계 표준시(UTC) 기준이라 KST보다 9시간 빠르게 적어야 한다 (예: KST 6:30 = UTC 전날 21:30). 설정 방법은 [운영·배포](11_운영_배포.md)에서 다룬다. |
| 출력 | 그 회차의 처리 결과 (FR-02-6으로 저장) |
| 예외 | - ✅ 확정: 실행이 실패하면 GitHub가 보내는 실패 메일로 알 수 있게 둔다 (별도 기능 없음). 자동 재시도는 하지 않는다.<br>- ✅ 확정: 실행이 실패한 회차는 앱이 **직전 회차 결과**를 그대로 보여준다 (FR-04-2 예외 참고).<br>- ✅ 확정: 수동 실행 버튼(GitHub의 "Run workflow")도 켜 두어 시연·테스트 때 바로 돌릴 수 있게 한다. |
| 완료 기준 | - GitHub Actions 실행 기록에 하루 3번 실행이 남는다.<br>- 각 실행이 알림 시각(7·12·19시) 전에 끝난다 (NFR-01 참고). |

### FR-01-4 오늘의 화제 기사 모으기

| 구분 | 내용 |
|---|---|
| 입력 | 구글 뉴스 "주요 뉴스" RSS (한국어) — 가입·키 필요 없음 (✅) |
| 처리 | RSS에서 기사 목록을 받는다. 같은 사건의 다른 언론사 기사 목록이 **이미 묶여서** 온다 (✅).<br>- 관심 분야와 무관한 시사 뉴스 (✅).<br>- RSS에 나온 순서대로 위에서 **후보 5개 묶음**을 가져온 뒤, 그중 **1~3개**를 고른다 (✅ 최대 3·최소 1, v1.3 / 고르는 방법은 아래 "묶음 수" 상자 ⏳). |
| 출력 | 오늘의 화제 기사 묶음 목록 (✅ 1~3개) → FR-02로 넘김 |
| 예외 | - 구글 뉴스 링크는 구글을 한 번 거치는 주소라 원문 주소를 바로 알기 어렵다 (기획서 제약 C4). **해결 방법은 [아키텍처·ADR](08_아키텍처_ADR.md)에서 정한다** (기획서에서도 미정).<br>- ✅ 확정: RSS를 못 받으면(오류·빈 목록) 이 페이지는 이번 회차를 건너뛰고 직전 회차 결과를 유지한다. |
| 완료 기준 | - 한 번 실행에 오늘의 화제 묶음이 1~3개 만들어진다 (RSS가 정상일 때).<br>- 각 묶음에 원문 기사 제목·링크·언론사·날짜가 들어 있다. |

### FR-01-5 나의 관심 분야 기사 모으기

| 구분 | 내용 |
|---|---|
| 입력 | 1순위 큰 분야 + 깊은 분야의 **검색 키워드** (기획서 분야 목록 ✅), 네이버 뉴스 검색 API (무료 가입 후 키 발급, ✅) |
| 처리 | 깊은 분야의 키워드로 네이버 뉴스 검색 API를 호출한다 (✅).<br>- ✅ 확정: 키워드마다 **최신순으로 20개**씩 받는다.<br>- ✅ 확정: **최근 24시간 안**에 나온 기사만 쓴다.<br>- ✅ 확정: 같은 원문 링크는 한 번만 남긴다 (중복 제거).<br>- 그 뒤 FR-02-1에서 같은 사건끼리 묶는다. |
| 출력 | 나의 관심 분야 기사 묶음 목록 (✅ 1~3개, v1.3) → FR-02로 넘김 |
| 예외 | - ✅ 확정: 24시간 안의 기사가 너무 적으면(예: 묶음을 1개도 못 만들면) 기간을 48시간으로 한 번 늘려 다시 찾는다. 그래도 적으면 **만들어진 만큼만** 쓴다.<br>- ✅ 확정: 네이버 API 오류(키 오류·한도 초과 등)면 이 페이지는 이번 회차를 건너뛰고 직전 회차 결과를 유지한다. |
| 완료 기준 | - 사용자가 "과학 → 우주"를 골랐다면 "우주, NASA, 누리호" 키워드로 검색한 기사만 들어간다.<br>- 한 번 실행에 묶음이 제안 개수(3개) 이하로 만들어진다. |

### FR-01-6 추천 뉴스 기사 모으기

| 구분 | 내용 |
|---|---|
| 입력 | 2순위 큰 분야의 **모든 깊은 분야 키워드** (✅), 네이버 뉴스 검색 API |
| 처리 | 깊은 분야를 고르지 않으므로 그 큰 분야의 깊은 분야 키워드를 **골고루 섞어** 검색한다 (✅).<br>- ✅ 확정 ("골고루"의 구체적 방법): 깊은 분야마다 대표 키워드 1개씩(목록의 첫 번째 키워드)으로 검색해, 깊은 분야마다 결과를 같은 수만큼 모은다.<br>- 최신순·24시간·중복 제거는 FR-01-5와 같은 제안값을 쓴다 (✅). |
| 출력 | 추천 뉴스 기사 묶음 목록 (✅ 1~3개, v1.3) → FR-02로 넘김 |
| 예외 | FR-01-5와 같다. |
| 완료 기준 | - 2순위로 "경제"를 골랐다면 금융·증권, 부동산 등 여러 깊은 분야의 기사가 섞여 들어간다.<br>- 한 번 실행에 묶음이 제안 개수(3개) 이하로 만들어진다. |

> **✅ 확정 (사용자 결정, v1.3) — 페이지마다 묶음은 최대 3개, 최소 1개.** 날마다 중요하거나 흥미로운 기사가 있는 날도 없는 날도 있으므로, 그날 볼 만한 것만 1~3개 보여준다. 한 번 실행에 최대 9개(3 + 3 + 3).
> (이전 v1.2 값 "11개 = 5 + 3 + 3"은 폐기. 페이지에 기사가 많으면 관심이 분산된다는 사용자 의견.)
>
> ✅ 확정 (사용자 결정, v1.4) — **몇 개를 보여줄지 정하는 방법**: 페이지마다 후보 묶음을 최대 5개 만든 뒤, 그 제목 목록을 AI에 한 번 보내 **"상식으로 알 만하거나 흥미로운 것만 1~3개 골라줘(볼 만한 게 적으면 적게)"** 라고 고르게 한다. 관심 분야·추천 뉴스는 FR-02-1의 "AI로 묶기" 호출에서 함께 고르게 하고(호출 추가 없음), 오늘의 화제는 RSS 상위 5개 묶음을 놓고 고르는 호출이 회차당 1번 늘어난다. AI 고르기가 실패하면 순서대로 위에서 3개를 쓴다.

### FR-01-7 3개 페이지 화면 표시

| 입력 | Firestore에 저장된 최신 회차 결과 |
| 처리 | 앱은 결과를 **보여주기만** 한다 (✅). 페이지 3개: 오늘의 화제 / 나의 관심 분야 / 추천 뉴스 (✅).<br>- ✅ 확정: 페이지는 화면 위쪽 **탭 3개**로 넘긴다 (자세한 배치는 [화면 설계서](04_화면설계서.md)).<br>- ✅ 확정: 목록의 한 칸에는 **어그로 한 줄 + 종합 기사 제목**을 보여준다.<br>- ✅ 확정: 순서는 서버가 정한 순서(오늘의 화제는 RSS 순서) 그대로.<br>- ✅ 확정: 앱을 열 때마다 최신 회차를 다시 읽는다. 아래로 당겨 새로고침도 지원한다. |

## 4. 기능 상세 — FR-02 여러 기사를 한 기사로 정리

### FR-02-1 같은 사건 기사 묶기

| 구분 | 내용 |
|---|---|
| 입력 | FR-01-4~6에서 모은 원문 기사 목록 |
| 처리 | - **오늘의 화제**: 구글 뉴스 RSS가 같은 사건 기사를 이미 묶어서 주므로 그 묶음을 그대로 쓴다 (✅).<br>- **나의 관심 분야 / 추천 뉴스**: 네이버 검색 결과는 묶여 있지 않으므로 같은 사건끼리 묶어야 한다 (기획서 사용 흐름 [2] ✅). **묶는 방법은 미정.**<br>- ✅ 확정: 페이지마다 기사 **제목 목록을 AI에 한 번 보내** "같은 사건끼리 묶고, 많이 보도된 순서로 정렬"하게 한다. 가장 쉬운 방법이다.<br>- ✅ 확정: 묶음 하나에 원문 기사는 **최대 5개**까지만 쓴다 (AI에 보내는 글 양 제한). |
| 출력 | 페이지별 기사 묶음 (묶음마다 원문 기사 1~5개) |
| 예외 | - ✅ 확정: 같은 사건 기사가 1개뿐인 묶음도 허용한다 (그 기사 하나로 종합 기사 작성).<br>- ✅ 확정: AI 묶기가 실패하면 기사를 묶지 않고 최신 기사 순서대로 1개씩 묶음으로 쓴다. |
| 완료 기준 | - 한 묶음 안의 기사들이 같은 사건을 다룬다 (사람이 10개 묶음을 눈으로 확인해 8개 이상 맞으면 통과).<br>- 묶음마다 원문 기사가 5개를 넘지 않는다. |

> ⚠ 이 제안을 채택하면 AI 호출이 한 번 실행에 2번(관심 분야 1 + 추천 1) 늘어 **하루 약 39번**이 됩니다 (기획서 5-4 가정 33번 + 6번). 기획서에 적힌 Flash-Lite 무료 한도(외부 자료 기준 하루 약 500회) 안이지만, 실제 한도는 가입 후 AI Studio에서 확인해야 합니다 (기획서 5-4 ✅).

### FR-02-2 원문 본문 추출

| 구분 | 내용 |
|---|---|
| 입력 | 묶음 안 원문 기사의 링크 |
| 처리 | 원문 링크를 열어 **본문 추출 라이브러리**(예: 파이썬 `trafilatura`)로 글자만 뽑는다 (✅). |
| 출력 | 기사별 본문 글자 (또는 실패 표시) |
| 예외 | - 추출에 실패하면 **요약(검색 결과의 몇 줄 요약)만으로** 작성한다 (✅).<br>- ✅ 확정 — "실패"의 기준: ① 페이지를 열지 못함(오류·10초 넘게 응답 없음) ② 뽑은 글자가 **200자 미만** ③ 라이브러리가 빈 값을 줌. 셋 중 하나면 실패로 본다.<br>- ✅ 확정: 본문이 너무 길면 기사당 앞부분 **3,000자**까지만 쓴다.<br>- ✅ 확정 (오늘의 화제): 구글 뉴스 RSS는 기사 요약을 따로 주지 않으므로, 본문 추출이 모두 실패한 묶음은 **원문 기사 제목들만으로** 짧게 작성하고, 그것도 어려우면(제목 1개뿐 등) 그 묶음을 건너뛰고 다음 순서 묶음을 쓴다. 원문 주소를 얻는 방법(제약 C4)은 [아키텍처·ADR](08_아키텍처_ADR.md)에서 정한다. |
| 완료 기준 | - 추출에 성공한 기사는 본문으로, 실패한 기사는 요약으로 종합 기사가 만들어진다.<br>- 원문 사이트 하나가 응답하지 않아도 전체 실행이 멈추지 않는다. |

### FR-02-3 종합 기사 작성

| 구분 | 내용 |
|---|---|
| 입력 | 묶음 1개의 원문 기사들(제목·본문 또는 요약·언론사·날짜·링크) |
| 처리 | AI(Gemini API 무료 요금제 **Flash-Lite**, ✅)에 보내 한 편의 종합 기사를 쓰게 한다.<br>- 본문은 **복사가 아니라 AI가 새로 쓴 정리** + 원문 링크 형태 (✅, 저작권 제약 C2).<br>- 여러 기사를 모아 **풍부하고 결론까지 있는 정보**를 준다 (기획서 1-5 원칙 1 ✅).<br>- ✅ 확정: **묶음 1개당 AI 호출 1번**으로 종합 기사 + 어려운 단어 해설 + 어그로 한 줄을 **한꺼번에** 받는다 (기획서 5-4의 "하루 33번" 계산과 맞춤). 결과는 JSON 형식으로 받는다.<br>- ✅ 확정 — 종합 기사 형식: **제목 1줄 + 본문 600~1,000자 + 마지막에 "한 줄 결론"**. 비전공자도 이해할 쉬운 말투.<br>- ✅ 확정: 원문 문장을 그대로 길게 옮기지 말 것을 지시문에 넣는다. |
| 출력 | 종합 기사(제목·본문·결론) |
| 예외 | - ✅ 확정: AI 호출이 실패하면(오류·한도 초과) **1번만 다시 시도**하고, 그래도 실패하면 그 묶음을 건너뛴다.<br>- ✅ 확정: AI 답이 약속한 형식(JSON)이 아니면 실패로 보고 같은 방식으로 처리한다.<br>- 기획서 3-2 ✅: AI 환각(사실 지어내기) 별도 대책은 두지 않는다. 출처 링크만 달고 문제가 생기면 그때 대응한다. |
| 완료 기준 | - 종합 기사에 제목·본문·결론이 모두 있다.<br>- 본문 길이가 제안 범위(600~1,000자) 안이다.<br>- 원문과 같은 문장이 길게(예: 50자 이상) 그대로 들어 있지 않다. |

### FR-02-4 어려운 단어 해설

| 구분 | 내용 |
|---|---|
| 입력 | FR-02-3에서 만든 종합 기사 |
| 처리 | - 서버 쪽: AI가 종합 기사 속 어려운 단어를 고르고 쉬운 해설을 쓴다 (✅, FR-02-3과 같은 호출).<br>- ✅ 확정: 종합 기사 1편당 **3~5개**. 해설은 1~2문장(100자 안팎).<br>- 앱: 그 단어에 **밑줄**을 긋고, **탭(터치)하면 해설**을 띄운다 (✅).<br>- ✅ 확정: 해설은 화면 아래에서 올라오는 작은 창으로 보여주고, 바깥을 누르면 닫힌다. |
| 출력 | 단어 목록(단어·해설), 화면의 밑줄 + 해설 창 |
| 예외 | - ✅ 확정: AI가 고른 단어가 본문에 실제로 없으면 그 단어는 버린다 (밑줄을 그을 수 없으므로).<br>- ✅ 확정: 같은 단어가 본문에 여러 번 나오면 **처음 나온 곳에만** 밑줄을 긋는다.<br>- ✅ 확정: 해설 단어가 0개여도 종합 기사는 정상 표시한다. |
| 완료 기준 | - 종합 기사 화면에서 밑줄 단어를 누르면 해설이 뜨고, 닫을 수 있다.<br>- 밑줄 단어는 모두 본문에 있는 단어다. |

### FR-02-5 출처 링크 표시

| 구분 | 내용 |

| 입력 | 묶음에 쓰인 원문 기사 목록 (제목·언론사·링크) |
| 처리 | 종합 기사 화면에 **항상 출처 기사 링크**를 단다 (✅).<br>- ✅ 확정: 본문 아래 "출처" 칸에 "언론사 · 기사 제목" 형태로 나열하고, 누르면 휴대폰 기본 인터넷 앱(브라우저)으로 원문을 연다. |

| 완료 기준 | - 모든 종합 기사 화면에 출처가 1개 이상 보인다.<br>- 출처를 누르면 원문 기사가 브라우저로 열린다. |

### FR-02-6 처리 결과 저장

| 구분 | 내용 |
|---|---|
| 입력 | 회차별 종합 기사·단어 해설·어그로 한 줄·출처 |
| 처리 | 스크립트가 결과를 **Firebase Firestore**에 올리고, 앱은 읽기만 한다 (✅).<br>- ✅ 확정: 회차마다 "실행 기록"(실행 시각, 성공/실패, 만든 묶음 수)을 함께 남긴다.<br>- ✅ 확정: 지난 결과는 **지우지 않고 쌓아 둔다** (2주 사용 동안 다시 보기·클릭 기록과 연결). 무료 저장 용량 안에서 충분한 양이다. |
| 출력 | Firestore의 결과 문서 (구조는 [9장 데이터 요약](#9-데이터-요약) 참고, 확정은 [데이터 모델](06_데이터모델_ERD.md)) |
| 예외 | - ✅ 확정: 일부 묶음만 실패하면 **성공한 묶음만** 저장한다. 하나도 성공하지 못하면 이번 회차를 저장하지 않고 앱은 직전 회차를 보여준다.<br>- ✅ 확정: 저장 도중 오류가 나면 실행 실패로 남긴다 (GitHub 실패 메일). |
| 완료 기준 | - 실행이 끝나면 Firestore 콘솔에서 이번 회차 결과와 실행 기록이 보인다.<br>- 앱이 그 결과를 읽어 화면에 표시한다. |

### FR-02-7 종합 기사 화면

| 구분 | 내용 |
|---|---|
| 입력 | 목록 칸 누름(FR-01-7) 또는 알림 누름(FR-04-3) |
| 처리 | 종합 기사를 보여준다. 화면 구성(✅ 기획서 5-2): 종합 기사 본문, 출처 링크(FR-02-5), 단어 탭 해설(FR-02-4), 안내 문구(FR-03-3).<br>- ✅ 확정 — 위에서부터 순서: 어그로 한 줄 → 안내 문구 → 종합 기사 제목 → 본문(밑줄 단어 포함) → 한 줄 결론 → 출처. |

| 예외 | - ✅ 확정: 열려는 종합 기사를 찾을 수 없으면(지워졌거나 아직 받지 못함) "기사를 불러오지 못했어요" 안내 후 해당 페이지 목록으로 돌아간다.<br>- ✅ 확정: 인터넷이 없어도 이미 받아 둔 기사는 볼 수 있다. |
| 완료 기준 | - 목록 또는 알림에서 들어오면 종합 기사, 출처, 안내 문구가 한 화면(스크롤)에 모두 보인다.<br>- 뒤로 가기를 누르면 목록 화면으로 돌아간다. |

## 6. 기능 상세 — FR-04 사용자에게 알림 보내기

### FR-04-1 알림 권한 받기와 알림 예약

| 구분 | 내용 |
|---|---|
| 입력 | 앱 첫 실행, 알림 시각 |
| 처리 | **안드로이드 알림만** 쓴다 (✅). 앱이 **스스로 예약하는 알림**이며, 서버에서 알림을 보내는 기능(푸시 서버)은 쓰지 않는다 (✅).<br>- 알림 시각 (✅): 하루 3번 — **아침 7시, 점심 12시, 저녁 19시**.<br>- ✅ 확정: 안드로이드 13 이상은 알림을 띄우려면 사용자 허락(알림 권한)이 필요하므로, 분야 선택(FR-01-1)을 마친 직후 권한을 요청한다.<br>- ✅ 확정: 휴대폰을 껐다 켜도 알림 예약이 다시 걸리게 한다.<br>- 구체적인 안드로이드 기술(예약 방식)은 [아키텍처·ADR](08_아키텍처_ADR.md)에서 정한다. |
| 출력 | 7·12·19시 알림 예약 |
| 예외 | - ✅ 확정: 알림 권한을 거부하면 앱 첫 화면 위에 "알림을 켜야 뉴스가 먼저 찾아와요" 안내와 설정 이동 버튼을 보여준다.<br>- 안드로이드는 배터리 정책 때문에 예약 동작이 늦거나 막히기도 한다 (기획서 제약 C7). ✅ 확정: 정확한 시각을 보장하지 않고 **최대 30분 정도 늦는 것은 허용**한다 (NFR-03 참고). |
| 완료 기준 | - 권한을 허락하면 다음 7·12·19시 중 가장 가까운 시각에 알림이 온다.<br>- 휴대폰을 다시 켠 뒤에도 알림이 온다. |

### FR-04-2 알림 띄우기

| 구분 | 내용 |
|---|---|
| 입력 | 알림 시각, Firestore의 최신 회차 결과 |
| 처리 | 앱이 알림 시각에 **최신 어그로 한 줄을 읽어** 알림을 띄운다 (✅). 알림에 어그로 한 줄을 표시한다 (✅). **위젯 없음** (✅).<br>- **어떤 한 줄을 띄울지 ✅ (사용자 결정, v1.1)**: 이번 회차에 만든 한 줄들(3개 페이지 전체) 중 **가장 흥미로운(또는 기사 내용이 풍부한) 한 줄 1개**.<br>- ✅ 확정 — 고르는 방법: 스크립트가 저장 직전에 이번 회차 한 줄 목록을 **AI에 한 번 보내 가장 흥미로운 1개를 고르게** 하고, 결과에 "알림용"으로 표시해 저장한다. 앱은 표시된 것을 읽기만 한다. (AI 호출 회차당 1번, 하루 3번 늘어남)<br>- ✅ 확정 — AI 고르기가 실패하면 **원문 기사 수가 가장 많은 묶음**(내용이 가장 풍부한 묶음)의 한 줄을 쓴다.<br>- ✅ 확정 — 한 번에 알림 **1개**만 띄운다.<br>- ✅ 확정 — 알림 제목은 "뉴스 봐", 내용은 어그로 한 줄. |
| 출력 | 휴대폰 알림 1개 |
| 예외 | - ✅ 확정: 알림 시각에 인터넷이 없거나 새 결과가 없으면(서버 실행 실패·지연) **직전 회차** 결과를 쓴다. 직전 회차의 같은 한 줄을 이미 알림으로 보냈다면 이번 알림은 **보내지 않는다** (같은 알림 반복 방지).<br>- ✅ 확정: "알림용" 표시가 없으면 오늘의 화제 1번째 묶음의 한 줄로 대신한다. |
| 완료 기준 | - 7·12·19시에 알림이 오고, 알림 내용이 Firestore에서 "알림용"으로 표시된 어그로 한 줄과 같다.<br>- 서버 실행이 실패한 회차에 같은 알림이 두 번 오지 않는다. |

### FR-04-3 알림 누르면 종합 기사로 이동

| 구분 | 내용 |
|---|---|
| 입력 | 사용자의 알림 누름 |
| 처리 | 알림을 누르면 **해당 종합 기사**로 들어간다 (✅). 앱이 꺼져 있어도 앱을 열고 바로 그 기사 화면(FR-02-7)을 보여준다. |
| 출력 | 종합 기사 화면 |
