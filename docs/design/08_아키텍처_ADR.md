> - **✅ 확정** = 기획서·기능명세서·화면 설계서에서 이미 ✅로 정해진 내용입니다. 근거 위치를 함께 적었습니다.
> - 이 문서에서 처음 필요해진 기술 결정(ADR-005~011)은 선택지를 비교해 추천안을 적었고, **v1.1에서 모두 확정**됐습니다(사용자 결정 또는 "수정이 쉬운 부분은 추천대로"). 남은 ⏳는 없습니다.
> - 추천 기준은 언제나 **"대학 과제로 가장 쉽게 만들 수 있는 것"**, 그다음 "비용 0원", "확정된 기능을 지킬 수 있는가" 순서입니다.
> - 상태 기호: ✅ 완료(확정) · ⚠ 부분 · 🔴 미작성 · ⏳ 진행
>
> **약어·용어 풀이**
> - **ADR**(Architecture Decision Record, 설계 결정 기록): "무엇을 왜 그렇게 정했는지, 다른 선택지는 왜 버렸는지"를 한 건씩 남기는 기록
> - **FR**(Functional Requirement, 기능 요구) · **NFR**(Non-Functional Requirement, 비기능 요구) · **SLO**(Service Level Objective, 서비스 목표 수준): [기능명세서](03_기능명세서.md)의 번호를 그대로 씁니다.
> - **API**(Application Programming Interface, 프로그램 간 통신 규격) · **RSS**(Really Simple Syndication, 새 글 목록을 내보내는 형식) · **AI**(Artificial Intelligence, 인공지능)
> - **SDK**(Software Development Kit, 개발 도구 묶음): 어떤 서비스를 내 프로그램에서 쉽게 쓰도록 그 회사가 제공하는 부품 모음
> - **JSON**(JavaScript Object Notation): "이름: 값" 형태로 데이터를 적는 글자 형식
> - **KST**(Korea Standard Time, 한국 표준시) · **UTC**(Coordinated Universal Time, 세계 표준시 — KST보다 9시간 느림)
> - **C4 모델**: 시스템 그림을 "① 전체 맥락 → ② 큰 덩어리(컨테이너) → ③ 덩어리 속 부품 → ④ 코드" 4단계로 점점 확대해 그리는 방법
> - **크론**(cron): "매일 몇 시 몇 분에 실행"처럼 예약 시각을 적는 형식
> - **도즈**(Doze, 잠자기 모드): 안드로이드 휴대폰이 오래 놓여 있으면 배터리를 아끼려고 앱의 예약 작업·인터넷 사용을 미뤄 두는 기능
> - **알람매니저**(AlarmManager): 안드로이드가 "몇 시에 이 앱을 깨워 줘"를 대신 기억해 주는 기본 기능
> - **워크매니저**(WorkManager): 안드로이드에서 "조건이 맞으면(예: 인터넷 연결 시) 이 작업을 언젠가 꼭 실행해 줘"를 맡기는 구글 공식 부품
> - **서비스 계정**: 사람이 아니라 프로그램(여기서는 파이썬 스크립트)이 Firebase에 접속할 때 쓰는 전용 계정·열쇠 파일
> - **Secrets**(GitHub 비밀 저장소): GitHub에 비밀번호·키를 코드와 따로 숨겨 두는 칸

## 1. 시스템 구조도

### 1-1. 1단계 — 전체 맥락 (누가·무엇과 이어지나) ✅

    │              │              │              │
    ▼              ▼              ▼              ▼

- 우리가 직접 만든 **서버 창구(API)는 없습니다** ([기능명세서 8장](03_기능명세서.md) ✅). 스크립트가 바깥 서비스를 부르고, 앱은 저장소를 직접 읽습니다.
- 서버에서 휴대폰으로 알림을 보내는 기능(푸시 서버)은 **쓰지 않습니다** ✅. 알림은 앱이 스스로 예약합니다.

### 2-3. 처리 흐름 ① — 하루 3번 예약 실행 (서버 쪽) ✅

> 근거: [기능명세서 2장](03_기능명세서.md) ✅. 괄호 안 숫자는 회차당 AI 호출 수(최대).

```
[K1] 6:30 / 11:30 / 18:30 KST 시작
  │
  ▼ ① D1 사용자 설정 읽기 ─ 없으면 "오늘의 화제만" 처리 (FR-01-2 예외)
  ▼ ② 기사 모으기
  │    · 오늘의 화제: 구글 뉴스 RSS 상위 5개 묶음 → 원문 주소 바꾸기(ADR-007)
  │    · 관심 분야 / 추천: 네이버 검색 (최신순 20개, 24시간 → 부족하면 48시간, 중복 제거)
  │    · 다른 분야 8개: 분야마다 대표 키워드로 10개 (FR-01-9)
  ▼ ③ 묶기·고르기
  │    · 오늘의 화제: AI가 5개 중 볼 만한 1~3개 고르기 (1)
  │    · 관심 분야·추천: AI가 같은 사건끼리 묶고 1~3개 고르기 (2)
  ▼ ④ 묶음마다 본문 추출 (실패 시 요약 / 오늘의 화제는 제목만)
  ▼ ⑤ 묶음마다 AI 1번: 종합 기사 + 단어 해설 + 어그로 한 줄 (JSON) (최대 9)
  ▼ ⑥ 다른 분야 한 줄: 8개 분야를 AI에 한 번에 (1)
  ▼ ⑦ 이번 회차 한 줄 중 "알림용" 1개 고르기 (1) ─ 실패 시 원문 기사 수가 가장 많은 묶음
  ▼ ⑧ Firestore 저장 (성공한 묶음만) + 실행 기록
끝 ─ 실패하면 GitHub 실패 메일 (자동 재시도 없음)
```

- 회차당 AI 호출 최대 **약 14번** × 하루 3번 = **약 42번** → NFR-05(하루 50번 이하) 안 ✅.
- 묶음 하나·원문 사이트 하나가 실패해도 **전체는 멈추지 않고 그 부분만 건너뜁니다** (NFR-10 ✅). 이를 위해 스크립트는 단계마다 "실패하면 기록하고 다음으로" 방식으로 짭니다.
- ⚠ 주의(구현 때 확인): Gemini 무료 요금제에는 하루 한도 말고 **분당 호출 한도**도 있습니다. 숫자는 AI Studio 화면에서 확인해야 하며, 필요하면 AI 호출 사이에 몇 초씩 쉬게 합니다. 이 경우에도 NFR-01(25분 안) 안에 충분히 들어올 것으로 봅니다(호출 14번 기준). 실측은 [테스트·QA](10_테스트_QA.md)에서.

### 2-4. 처리 흐름 ② — 알림 (휴대폰 쪽) ✅ (기술 ADR-006)

> 근거: FR-04-1·2·3 ✅. 아래 "깨우기·읽기" 기술 방식은 [ADR-006](#adr-006-안드로이드-알림-예약-기술) 제안입니다.

```
[예약] 분야 선택(S01) 직후 알림 권한 받기 → 다음 7/12/19시 중 가장 가까운 시각 1개 예약
   │                         (휴대폰 재부팅·시간 변경 시 다시 예약)
   ▼
[알림 시각] 안드로이드가 앱을 깨움
   ▼ Firestore에서 최신 회차의 "알림용" 한 줄 읽기
   │    · 인터넷 없음/새 결과 없음 → 휴대폰에 보관된 직전 회차 사용
   │    · 그 한 줄을 이미 알림으로 보냈다면 → 이번에는 보내지 않음 (중복 방지)
   │    · "알림용" 표시가 없으면 → 오늘의 화제 1번째 묶음의 한 줄
   ▼ 알림 1개 표시 (제목 "뉴스 봐", 내용 = 어그로 한 줄) + "마지막으로 보낸 한 줄" 기억
   ▼ 다음 시각 1개 다시 예약
   │
[사용자가 알림 누름] → 앱이 꺼져 있어도 S03 종합 기사 → 뒤로 가기 시 S02의 그 기사 탭
```

### 5-1. 파일별 역할 (제안)

| 파일 | 하는 일 | 바깥과의 연결 | 관련 FR |
|---|---|---|---|
| `main.py` | 처리 순서대로 다른 파일을 부르기만 함. 단계별 실패를 기록하고 다음 단계로 넘어감 | — | FR-01-3, NFR-10 |

| `collect.py` | 구글 RSS·네이버 검색으로 기사 모으기, 24→48시간·중복 제거 | A1, A2 | FR-01-4·5·6·9 |
| `google_link.py` | 구글 뉴스 링크 → 원문 주소 바꾸기 (실패하면 원래 링크 반환) | 구글 | FR-01-4 (C4) |
| `extract.py` | 본문 추출과 실패 판정(10초·200자·빈 값), 3,000자 자르기 | A3 | FR-02-2 |
| `ai_client.py` | **AI 호출 창구 1곳.** "지시문을 주면 JSON을 돌려주는" 함수 하나. 모델 이름·키는 설정값에서 읽음. 1번 재시도 | A4 | NFR-09, FR-02-3 예외 |
| `ai_tasks.py` | 묶기·고르기·종합 기사·다른 분야 한 줄·알림용 고르기 — **무엇을 시킬지**와 결과 형식 검사(40자 자르기, 본문에 없는 단어 버리기 등) | (ai_client 경유) | FR-02-1·3·4, FR-03-2, FR-04-2, FR-01-9 |
| `prompts/` 폴더 | 지시문 글 파일들, 어그로 예시 제목 15개 파일(사용자가 직접 작성 ✅) | — | FR-03-1 |
| `config` (설정값) | 시각·개수·글자 수 같은 숫자, 분야·키워드 목록, AI 모델 이름 | — | FR-01 분야 목록 |

### 5-2. AI 교체 원리 (그림)

```
 ai_tasks.py ──"이 지시문으로 JSON 줘"──▶ ai_client.py ──▶ Gemini Flash-Lite (지금)
                                              │
                                              └─ 바꿀 때: 이 파일 안의 호출 부분만 고침
                                                  · 같은 Gemini의 다른 모델 → 설정값(모델 이름)만 바꿈
                                                  · Claude API 등 다른 회사 → ai_client.py 한 파일만 다시 씀
```

- 다른 파일은 AI 회사 이름을 모릅니다. 그래서 AI를 바꿔도 **나머지 파일은 그대로**입니다 (NFR-09 ✅).

### ADR-005 안드로이드 앱 개발 방식

| 항목 | 내용 |
|---|---|
| 상태 | ✅ 확정 — 사용자 결정 (v1.1): 코틀린 네이티브 + 젯팩 컴포즈 |
| 관련 | FR-01-1·7·8, FR-02-4·5·7, FR-03-3, FR-04-1·2·3, NFR-02, NFR-11 |
| 배경 | 기획서는 "안드로이드 앱"까지만 정했습니다. 앱을 **어떤 언어·도구로 만들지** 정해야 합니다. 이 앱의 어려운 부분은 화면보다 **"정해진 시각에 앱이 깨어나 인터넷에서 한 줄을 읽어 알림을 띄우는 것"**(FR-04-2)입니다. |

**선택지 비교**

| 기준 | ① 코틀린(Kotlin) 네이티브 + 젯팩 컴포즈 | ② 플러터(Flutter, 다트 언어) | ③ 리액트 네이티브(React Native, 자바스크립트) |
|---|---|---|---|
| 설명 | 구글이 정한 안드로이드 공식 언어·화면 도구 | 구글이 만든 "한 번 만들어 안드로이드·아이폰 둘 다" 도구 | 메타가 만든 같은 목적의 도구 |
| 개발 도구 설치 | 안드로이드 스튜디오 하나 | 안드로이드 스튜디오 + 플러터 SDK | 안드로이드 스튜디오 + Node.js 등 |
| Firestore 연결 | 구글 공식 안드로이드 SDK, 설명서·예제가 가장 많음 | 공식 플러그인(FlutterFire) 있음, 설정 단계가 조금 더 많음 | 제3자 라이브러리 사용 |
| **알림 시각에 깨어나 Firestore 읽고 알림** (FR-04-2) | 안드로이드 기본 기능(알람매니저·워크매니저)을 **같은 언어로 바로** 씀. 공식 설명서 그대로 따라 하기 쉬움 | 알림 띄우기 부품은 쉬우나, "정해진 시각에 **화면 없이** 코드 실행 + Firestore 읽기"는 별도 부품 2~3개를 이어 붙여야 하고 설정이 까다로움 | 플러터와 비슷하거나 더 까다로움 |
| 재부팅 후 재예약 | 공식 방법(부팅 완료 신호 받기)을 직접 씀 | 부품이 일부 처리하나 위 "화면 없이 실행"과 엮이면 복잡 | 비슷 |
| 화면(탭 3개·밑줄 단어·해설 창) | 젯팩 컴포즈 기본 부품으로 가능 | 쉬움, 화면 만들기는 가장 편함 | 쉬움 |
| 나중에 아이폰 | 화면을 따로 새로 만들어야 함 | 같은 코드로 가능 | 같은 코드로 가능 |
| AI 코딩 도우미·검색 자료 | 매우 많음 | 많음 | 많음 |

- **추천안: ① 코틀린 네이티브 + 젯팩 컴포즈**
- 이유
  1. 이 앱의 가장 어려운 기능(알림 시각에 깨어나 읽기, 재부팅 재예약)이 **안드로이드 기본 기능 그 자체**라서, 중간 부품 없이 공식 설명서를 그대로 따를 수 있습니다. (가장 쉬움 기준)
  2. Firestore 공식 안드로이드 SDK를 그대로 쓰며, 인터넷 없을 때 이전 결과를 보여주는 기능(휴대폰 보관)도 기본으로 따라옵니다.
  3. 플러터의 장점인 "아이폰도 같이"는 **MVP 범위 밖**입니다(기획서 3-2 ✅ 아이폰·웹 제외).
- 버린 이유: ② 플러터 — 화면은 더 쉽지만, 핵심 기능인 "화면 없이 시각에 실행"에서 설정이 늘어남. ③ 리액트 네이티브 — 같은 이유 + Firestore 공식 SDK 아님.
- 감수할 점: 코틀린을 새로 배워야 합니다(플러터도 다트를 새로 배우는 것은 같음). 화면 만들기 자체는 플러터보다 약간 손이 더 갈 수 있습니다.
- ⚠ 사용자 확인: 이미 플러터나 다른 도구를 배워 본 경험이 있다면 "익숙한 것"이 가장 쉬울 수 있으므로 알려 주세요.

### ADR-006 안드로이드 알림 예약 기술

| 항목 | 내용 |
|---|---|
| 상태 | ✅ 확정 — 사용자 결정 (v1.1): **"정확한 시각" 권한 안내를 하지 않는다** → 아래 ② **대략 시각 알람만** 사용 (권한 확인·전환 코드 불필요). 구성 1·2·3·4번(다음 시각 1개씩 예약, 깨어나 읽기, 재부팅·시간 변경 재예약, 누르면 S03)은 그대로 적용 |
| 관련 | FR-04-1·2·3, NFR-03(최대 30분 정도 지연 허용, 03 v1.6), SLO-02, 제약 C7 |
| 배경 | 하루 3번 정해진 시각에 앱이 **깨어나서 Firestore를 읽고** 알림을 띄워야 합니다(FR-04-2 ✅). 확인된 사실(안드로이드 공식 설명서): ① 안드로이드 14부터 새로 설치한 앱은 **"정확한 시각 알람" 권한이 기본으로 꺼져 있고**, 사용자가 설정 화면에서 켜 줘야 합니다. 권한 없이 정확한 알람을 걸면 앱이 멈추므로 먼저 권한을 확인해야 합니다. 권한이 필요 없는 **"대략 시각 알람"**도 있습니다. ② 휴대폰을 끄면 예약된 알람이 지워지므로, 켜질 때 받는 "부팅 완료" 신호로 **다시 예약**해야 합니다(FR-04-1 ✅ 재부팅 후 재예약). ③ 휴대폰이 잠자기(도즈) 상태면 일반 예약 작업은 미뤄집니다. |

**선택지 비교**

| 기준 | ① 알람매니저 "정확한 시각" 알람 (+ 권한 없으면 ② 방식으로 자동 전환) | ② 알람매니저 "대략 시각" 알람만 | ③ 워크매니저만 |
|---|---|---|---|
| 시각 정확도 | 가장 정확 (잠자기 중에도 깨움) | 몇 분~그 이상 늦을 수 있음 (기기마다 다름, 실측 필요) | 잠자기 중에는 크게 늦을 수 있음 (특히 밤새 놓아둔 뒤 아침 7시) |
| NFR-03 (처음 기준 10분 안 → 30분으로 완화) | 지키기 쉬움 | 30분 기준이면 대체로 충족 예상 (실측 필요) | 넘길 가능성 큼 |
| 추가 허락 | 안드로이드 14 이상: 설정에서 "알람 및 리마인더" 허용 **1번** 필요 | 없음 | 없음 |
| 재부팅 후 | 부팅 완료 신호에서 직접 재예약 | 같음 | 워크매니저가 알아서 유지 |
| 만들기 난이도 | 보통 (권한 확인 + 전환 코드 약간) | 쉬움 | 쉬움 |

- (v1.0 추천안: ① 정확한 시각 알람 + 자동 전환 → **v1.1 사용자 결정으로 ② 대략 시각 알람만 채택**, 상태 칸 참고)
- 구성(개략)
  1. 다음 알림 시각(7·12·19시 중 가장 가까운 것) **1개만** 예약하고, 울리면 그다음 시각을 다시 예약합니다(하루 반복 예약보다 단순·정확).
  2. 깨어나면 짧은 작업으로 Firestore에서 "알림용" 한 줄을 읽어 알림을 띄웁니다. 인터넷이 막혀 있으면 휴대폰에 보관된 직전 결과를 쓰고, 같은 한 줄이면 보내지 않습니다(FR-04-2 예외 ✅).
  3. "부팅 완료"와 "시간·시간대 변경" 신호를 받아 다시 예약합니다.
  4. 알림을 누르면 그 종합 기사 번호를 담아 S03을 엽니다(FR-04-3 ✅).
- 이유: 성공 기준 ① 시연(알림 → 클릭 → 종합 기사)과 SLO-02(42회 중 38회)를 가장 확실하게 지킬 수 있습니다. 권한을 안 켜도 ② 방식으로 계속 동작하므로 앱이 멈추지 않습니다.
- 버린 이유: ② — 권한 화면은 없지만 아침 7시처럼 밤새 잠자기 뒤에는 늦어질 위험. ③ — 같은 이유로 더 늦을 수 있음.
- 감수할 점·확인 필요
  - ⚠ **화면 설계서(04)에 없는 단계가 생깁니다**: 안드로이드 14 이상이면 "알람 및 리마인더 허용" 설정을 켜야 정확해집니다. 이 권한을 **언제·어떻게 안내할지**(예: 알림 권한 직후 설정 화면으로 한 번 보내기 / 안내 없이 대략 시각으로만 동작)는 사용자 결정이 필요합니다. 결정되면 04를 고쳐야 합니다.
  - ⚠ **확인 못 한 것**: 잠자기 중 알람으로 깨어났을 때 Firestore를 읽을 인터넷이 항상 허락되는지는 이번에 공식 자료로 확인하지 못했습니다. 읽지 못하면 확정된 예외 동작(직전 회차 사용·중복이면 생략)으로 처리되므로 앱이 멈추지는 않습니다. 실제 휴대폰 실측은 [테스트·QA](10_테스트_QA.md)에서 합니다.
  - 일부 제조사(예: 삼성)는 자체 절전 기능이 더 강합니다. 실측에서 알림이 자주 늦으면 휴대폰 설정의 "절전 예외 앱"에 넣는 것을 사용 안내로 둡니다(앱 기능 추가 없음).

### ADR-007 구글 뉴스 링크의 원문 주소 얻기 (제약 C4)

| 항목 | 내용 |
|---|---|
| 상태 | ✅ 확정 — 추천안대로 (v1.1, 사용자: "수정이 쉬운 부분은 추천대로") |
| 관련 | FR-01-4, FR-02-2, FR-02-5, 제약 C4 |
| 배경 | 구글 뉴스 RSS의 기사 링크는 `news.google.com/rss/articles/…` 처럼 **구글을 거치는 주소**입니다. 본문 추출(trafilatura)은 원문 주소가 있어야 합니다. 또 출처 링크(FR-02-5)도 가능하면 원문 주소가 좋습니다. |
| 조사 결과 (2026-10-26 웹 검색) | - 파이썬 부품 **`googlenewsdecoder`**(PyPI 공개)가 구글 뉴스 링크를 원문 주소로 바꿔 줍니다. 구글 내부 창구를 흉내 내는 방식이라, **구글이 요청을 너무 많다고 막으면(429 오류) 실패**할 수 있고 구글 쪽이 바뀌면 동작이 멈출 수 있습니다.<br>- 비슷한 부품(gnews)도 해독에 실패하면 **원래 구글 링크를 그대로 돌려준다**고 안내합니다.<br>- **확인하지 못한 것**: ① 구글 링크를 단순히 따라가기(주소 이동 따라가기)만으로 원문 주소를 얻을 수 있는지 — 예전에는 됐다는 자료가 있으나 지금도 되는지 공식 확인 못 함. ② 휴대폰 브라우저에서 구글 링크를 열면 원문으로 넘어가는지 — 일반적으로 그렇게 알려져 있으나 이번에 직접 확인 못 함(구현 때 확인). ③ `googlenewsdecoder`의 현재 성공률 — 실측 필요. |

**선택지 비교**

| 기준 | ① `googlenewsdecoder`로 바꾸기, 실패하면 구글 링크 그대로 | ② 기사 제목으로 네이버 검색 API를 다시 불러 원문 링크 찾기 | ③ 원문 주소 포기 — 구글 링크를 출처로만 두고 제목만으로 작성 |
|---|---|---|---|
| 만들기 난이도 | 쉬움 (부품 설치 + 함수 1번 호출) | 보통 (제목이 똑같지 않으면 엉뚱한 기사가 걸릴 수 있어 비교 규칙 필요) | 가장 쉬움 |
| 본문 추출 가능 | 대부분 가능 (실패분만 제목으로) | 찾은 경우만 가능 | 불가 → 오늘의 화제 종합 기사가 늘 제목만으로 작성됨 (내용 빈약, 기획서 원칙 1과 어긋남) |
| 안정성 | 구글이 바꾸면 멈출 수 있음 → 그래도 ③으로 자동 후퇴 | 네이버 API는 안정적 | 안정적 |
| 사용량 | 회차당 최대 25개 링크 (5묶음 × 5기사) 정도라 적음 | 네이버 호출 회차당 최대 25회 추가 (한도 25,000회 안) | 없음 |

- **추천안: ① `googlenewsdecoder`로 바꾸기 → 실패하면 ③(구글 링크 그대로 + 기능명세서의 "제목만으로 작성/건너뛰기" 예외)**
- 이유: 가장 적은 코드로 오늘의 화제 종합 기사의 내용을 채울 수 있고, 실패해도 **이미 확정된 예외 동작**(FR-02-2 ✅ 제목만으로 작성 → 불가 시 다음 묶음)으로 자연스럽게 이어집니다. 해독 부분은 `google_link.py` 한 파일에 가둬서, 나중에 ②로 바꾸기 쉽게 합니다.
- 감수할 점: 구글 쪽 변화로 갑자기 동작이 멈출 수 있습니다. 실행 기록(D2)에 "원문 주소 바꾸기 성공 수"를 경고로 남겨 알아챌 수 있게 하는 것을 제안합니다(세부는 [관측·로깅](12_관측_로깅_감사.md)).
- 출처 링크(FR-02-5): 원문 주소를 얻었으면 원문 주소, 못 얻었으면 구글 링크를 그대로 저장합니다.

### ADR-008 AI 교체 가능 구조

| 항목 | 내용 |
|---|---|
| 상태 | ✅ 확정 — 추천안대로 (v1.1, 사용자: "수정이 쉬운 부분은 추천대로") |
| 관련 | NFR-09, ADR-002, FR-02-3 예외(1번 재시도), FR-02-3(JSON 결과) |
| 배경 | AI 한도가 줄거나 품질이 아쉬우면 다른 Gemini 모델이나 Claude API 등으로 바꿔야 합니다(기획서 5-4 ✅). |

**선택지 비교**

| 기준 | ① AI 호출 파일 1개(`ai_client.py`)에 함수 1개 + 모델 이름은 설정값 | ② AI 회사별로 클래스(부품 틀)를 따로 만들고 설정으로 고르기 | ③ 여러 AI 회사를 한 방식으로 부르는 통합 라이브러리 사용 |
|---|---|---|---|
| 처음 만들기 | 가장 쉬움 | 구조 공부 필요 | 라이브러리 사용법 공부 필요 |
| 같은 회사 다른 모델로 교체 | 설정값 한 줄 | 설정값 한 줄 | 설정값 한 줄 |
| 다른 회사로 교체 | 그 파일 하나만 다시 씀 | 새 클래스 추가 | 설정값 + 키 |
| 부품 추가 의존 | 공식 Gemini 부품 1개 | 회사 수만큼 | 큰 라이브러리 1개 (업데이트 영향) |

- **추천안: ①**
- 이유: AI를 실제로 바꿀 일이 생길지 모르는 단계에서 ②·③은 미리 일을 늘립니다. ①만으로도 "다른 파일은 AI 회사를 모른다"는 원칙이 지켜져, 바꿀 때 **한 파일만** 고치면 됩니다.
- 규칙(제안): ① 모든 AI 요청은 `ai_client.py`를 거친다 ② 결과는 항상 JSON으로 받아 형식 검사 후 사용, 형식이 틀리면 실패로 본다(FR-02-3 ✅) ③ 실패 시 1번만 재시도(FR-02-3 ✅) ④ 지시문은 코드가 아니라 `prompts/` 글 파일에 둔다(FR-03-1 ✅ 예시 제목 파일과 같은 방식).

### ADR-009 파이썬 스크립트 모듈 구성

| 항목 | 내용 |

| 상태 | ✅ 확정 — 추천안대로 (v1.1, 사용자: "수정이 쉬운 부분은 추천대로") |
| 관련 | FR-01-3~6·9, FR-02-1~4·6, FR-03-1·2, FR-04-2, NFR-01, NFR-10 |

**선택지 비교**

| 기준 | ① 파일 1개 (`main.py`에 전부) | ② 단계별 파일 6개 정도 ([5-1](#5-1-파일별-역할-제안) 표) | ③ 여러 층 폴더 + 클래스 구조 |

### ADR-010 코드 저장소 구성과 공개 여부

| 항목 | 내용 |
|---|---|
| 상태 | ✅ 확정 — 사용자 결정 (v1.1): **저장소 1개, 공개** (아래 ②). 비밀키는 GitHub Secrets에만 두고, AI 지시문·어그로 예시 제목은 공개됨을 감수. 앱 설치 파일은 올리지 않음(NFR-08) |
| 관련 | FR-01-3, NFR-04(0원), NFR-06(키 관리), NFR-08(공개 배포 안 함) |
| 배경 | 앱 코드와 스크립트를 GitHub에 올려야 GitHub Actions가 돌아갑니다. 저장소 개수와 **공개/비공개**를 정해야 합니다. |
| 조사 메모 (구현 전 GitHub 화면에서 다시 확인) | 알려진 내용(이번에 공식 문서로 다시 확인하지는 않음): 공개 저장소는 GitHub Actions 실행 시간이 무료로 넉넉하지만, **오랫동안(약 60일) 저장소에 변화가 없으면 예약 실행이 자동으로 꺼집니다.** 비공개 저장소는 무료 계정에 **한 달 실행 시간 한도**(약 2,000분)가 있습니다. 한 번 실행이 5분이면 한 달 약 450분으로 충분하지만, 최대치(25분 × 3번 × 30일 = 2,250분)까지 가면 넘을 수 있습니다. |

**선택지 비교**

| 기준 | ① 저장소 1개, **비공개**, 안에 `app/`·`script/` 폴더 | ② 저장소 1개, 공개 | ③ 저장소 2개 (앱·스크립트 따로) |
|---|---|---|---|
| 관리 쉬움 | 쉬움 (한 곳) | 쉬움 | 두 곳 관리 |
| 비용 | 실행 시간 한도 안이면 0원 (실측 필요) | 0원 | ①·② 중 무엇이냐에 따름 |
| 코드·지시문·예시 제목 노출 | 안 됨 | 누구나 봄 (키는 Secrets라 안전하지만, 어그로 예시 제목·지시문이 공개됨) | — |
| 공개 배포 안 함(NFR-08)과의 관계 | 잘 맞음 | 앱 설치 파일을 올리지 않으면 어긋나지는 않음 | — |

- (v1.0 추천안: ① 비공개 → **v1.1 사용자 결정으로 ② 공개 채택**, 상태 칸 참고)
- 채택 결과(공개): 한 곳에서 관리하고 실행 시간 한도 걱정이 없습니다. 앱 설치 파일은 올리지 않으므로 "공개 배포 안 함"(NFR-08)과 충돌하지 않습니다(코드만 공개). 비밀 보호는 [09](09_보안_개인정보.md) 4장.
- ⚠ 사용자 확인: **과제 제출 때 코드를 공개 저장소로 내야 하는지** 알려 주세요. 공개해야 하면 ②를 택하고, 지시문·예시 제목 공개를 감수하거나 제출용 사본을 따로 만드는 방법을 정해야 합니다.

## 10. 사용자 확인이 필요한 항목

> 사용자가 판단해야 하는 것만 중요한 순서로 적었습니다. 순수 기술 세부는 따로 모았습니다.

| 우선 | 질문 | 추천안 | 관련 |
|:---:|---|---|---|
| 1 | 앱 개발 방식을 **코틀린 네이티브**로 할까요? (이미 배워 본 도구가 있다면 알려 주세요) | 코틀린 + 젯팩 컴포즈 | ADR-005 |
| 2 | 안드로이드 14 이상에서 알림을 정시에 맞추려면 **"알람 및 리마인더" 허용을 설정에서 1번 켜야** 합니다. 알림 권한 직후 이 설정 화면으로 안내할까요, 아니면 안내 없이 "대략 시각"으로만 동작하게 할까요? (안내하면 화면 설계서 04를 고쳐야 함) | 알림 권한 직후 1번 안내 (거부해도 대략 시각으로 계속 동작) | ADR-006 |
| 3 | 과제 제출 때 코드를 공개해야 하나요? → ✅ **공개 저장소 1개** (v1.1 사용자 결정) | — | ADR-010 |
| 4 | 구글 뉴스 원문 주소는 **외부 부품(`googlenewsdecoder`)으로 바꾸고, 안 되면 구글 링크 그대로** 둘까요? (구글이 바꾸면 갑자기 안 될 수 있음을 감수) | 그렇게 | ADR-007 |

**추천대로 해도 무방한 순수 기술 세부**: ADR-008(AI 교체 구조), ADR-009(스크립트 파일 구성), ADR-011(파이썬 부품), ADR-006 안의 세부 구성(다음 시각 1개씩 예약, 재부팅·시간 변경 재예약).

## 12. 다음 문서로 넘기는 사항

### 12-1. [데이터 모델(06)](06_데이터모델_ERD.md) 작성자에게

1. D3 종합 기사에 **알림에서 열 기사를 가리킬 고유 번호**가 필요합니다(알림을 누르면 그 번호로 S03을 엶, FR-04-3). "최신 회차"와 "알림용" 한 줄을 앱이 **한 번의 읽기로 빨리** 찾을 수 있는 구조가 좋습니다(알림 시각에 깨어 있는 시간이 짧음, NFR-02·03).
2. D5 출처에 원문 링크가 **구글 경유 링크인지 원문 주소인지** 구분 항목을 둘지 검토(ADR-007).
3. D2 실행 기록의 "경고"에 **구글 링크 해독 성공/실패 수**, 예시 제목 파일 없음 경고(FR-03-1) 등을 담을 수 있게.
4. FR-01-9 "다른 분야 한 줄"(분야 이름 + 어그로 한 줄 + 원문 링크, 최대 8줄)의 저장 위치 — 기능명세서 9장 D1~D5에 명시되어 있지 않습니다. 회차별로 저장해야 합니다.
5. 휴대폰 안 보관(K7): ① 마지막으로 읽은 결과(앱용 Firestore 부품의 기본 보관 기능으로 충분한지) ② "마지막으로 알림 보낸 한 줄의 번호" 저장 칸.
6. 결과는 지우지 않고 쌓아 두므로(FR-02-6 ✅) 무료 저장 용량 안인지 대략 계산.

### 12-2. [보안·개인정보(09)](09_보안_개인정보.md) 작성자에게

1. ✅ 09에서 정함 — **앱의 Firestore 접근 방식**(A6): 회원 기능이 없으므로 예) Firebase 익명 로그인 + 접근 규칙, 또는 다른 방법. 앱은 D1 쓰기와 D2·D3 읽기만 하면 되고, D2·D3 쓰기는 스크립트만 해야 합니다.
2. ✅ 09에서 정함 — **Firebase 서비스 계정 열쇠**(A5)의 보관 위치 — 이 문서는 GitHub Secrets를 제안했습니다.
3. 저장소 공개 여부(ADR-010)에 따른 노출 범위 — 공개 저장소라면 지시문·예시 제목 공개, 실행 기록(Actions 로그) 공개 여부 확인. 로그에 키가 찍히지 않게 하는 규칙.
4. 외부 부품(`googlenewsdecoder` 등) 사용 시 버전 고정·출처 확인.
5. 안드로이드 권한 목록: 알림 권한, 부팅 완료 신호 받기 권한, 인터넷 권한. (정확한 시각 알람 권한은 쓰지 않음 — ADR-006 v1.1)
6. Gemini 무료 요금제 데이터 활용 조건(공개 기사만 전송, NFR-07 ✅) 재확인.
