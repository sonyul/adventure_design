> **이 문서를 읽는 법**
> - 이 문서는 [기능명세서](03_기능명세서.md)의 기능(FR)이 **휴대폰 화면에서 어떻게 보이고, 누르면 어디로 가는지**를 정리한 문서입니다.
> - **✅ 확정** = 기능명세서·기획서에 ✅로 이미 정해진 내용입니다. 근거 FR 번호를 함께 적었습니다.
> - 기능명세서에 없던 화면 세부는 작성자가 기본값을 제안했고, **사용자가 "전부 제안대로" 확정**했습니다 (v1.2). 어떤 것이 새로 추가된 세부인지는 [8장](#8-확인이-필요한-제안-항목-모음)(질문 기록)과 9장에 남겨 두었습니다. 본문의 "제안합니다" 표현은 확정된 내용으로 읽으면 됩니다.
> - 색·글꼴·간격 같은 디자인 세부는 [UI 디자인시스템 / IA](05_UI디자인시스템_IA.md)에서 정합니다. 이 문서는 **화면 구조·요소·이동** 위주입니다.
> - 상태 기호: ✅ 완료(확정) · ⚠ 부분 · 🔴 미작성 · ⏳ 진행
>
> **약어·용어 풀이**
> - **FR**(Functional Requirement, 기능 요구): 시스템이 해야 하는 기능. 이 문서에서는 기능명세서의 세부 번호(FR-01-1 등)를 씁니다.
> - **NFR**(Non-Functional Requirement, 비기능 요구): "얼마나 빠르게·안정적으로" 같은 요구
> - **MVP**(Minimum Viable Product, 최소 기능 제품): 가설을 확인할 수 있는 가장 작은 첫 버전
> - **IA**(Information Architecture, 정보 구조): 메뉴와 화면이 어떻게 이어지는지의 구조
> - **목업**(mockup): 실제 앱을 만들기 전에 화면 모양을 미리 그려 본 시안
> - **탭**(tab): 화면 위쪽에 나란히 있는 이름표. 누르면 그 페이지로 바뀝니다. (손가락으로 "탭(터치)한다"와 구분하기 위해 이 문서에서는 화면 요소를 "탭", 누르는 행동을 "누른다"로 씁니다.)
> - **상단 바**(app bar): 화면 맨 위의 제목·버튼이 있는 띠
> - **아래에서 올라오는 창**(bottom sheet, 바텀 시트): 화면 아래쪽에서 올라와 내용 일부를 덮는 작은 창
> - **스낵바/배너**: 화면 위나 아래에 잠깐 또는 계속 떠 있는 한 줄 안내 띠
> - **아래로 당겨 새로고침**(pull to refresh): 목록을 손가락으로 아래로 끌어내렸다 놓으면 새 내용을 다시 읽어 오는 동작
> - **시스템 화면**: 우리 앱이 아니라 안드로이드가 직접 띄우는 화면(알림, 권한 묻는 창, 설정 앱, 인터넷 앱 등)

## 1. 화면 설계 원칙

### 1-1. 기본 조건 (✅)

| 항목 | 내용 | 근거 |
|---|---|---|
| 기기 | 안드로이드 휴대폰, **세로 화면** | 기획서 5-1, NFR-11 |
| 사용자 | 1명, **회원 가입·로그인 없음** | 기획서 2장, 3-2 |
| 언어 | 모든 화면 문구 한국어 | NFR-12 |
| 앱의 역할 | 서버 쪽이 만든 결과를 **보여주기만** 한다 (앱에서 기사를 만들지 않음) | 기획서 5-1, FR-01-7 |
| 알림 | 안드로이드 알림만 사용. **위젯·잠금화면 전용 화면 없음** | 기획서 3-1 FR-04, 3-2 |
| 화면 속도 | 목록·종합 기사 화면이 **3초 안에** 열린다 | NFR-02 |

### 1-2. 화면에 넣지 않는 것 (MVP 제외 ✅)

기획서 3-2와 기능명세서 결정에 따라 아래는 **어떤 화면에도 넣지 않습니다.**

- 기자 평가, AI 신뢰도(충실도) 분석, **보도 언론사 수 표시**
- 클릭 기록·반응 기록 화면 (FR-04-4 삭제, 기록은 사용자가 직접)
- 홈화면 위젯, 잠금화면 전용 화면
- 회원 가입·로그인·프로필
- 어그로 한 줄 A/B 테스트(문장 2개 번갈아 보여주기)

### 1-3. 분위기 원칙 — "깔끔한 뉴스 앱 느낌"

> 사용자가 원하는 분위기입니다. 구체적인 색·글꼴·크기는 [05 문서](05_UI디자인시스템_IA.md)에서 정합니다.

- **글이 주인공**: 꾸밈을 줄이고, 제목과 본문이 잘 읽히는 것을 가장 먼저 생각합니다.
- **밝은 바탕 + 강조색 한 가지**: 화면은 차분하게, 강조는 한 가지 색으로만 합니다.
- **여백 넉넉히**: 목록 칸 사이·문단 사이를 넉넉히 띄워 답답하지 않게 합니다.
- **사진 없음**: 저장하는 데이터에 기사 사진이 없으므로([기능명세서 9장](03_기능명세서.md#9-데이터-요약) D3·D5) 목록·기사 화면은 **글만으로** 구성합니다.
- **어그로 한 줄은 눈에 띄게, 안내 문구는 작고 조용하게**: 안내 문구는 작은 회색 글씨(✅ FR-03-3).

## 4. 화면별 설계

> 각 화면은 **목적 → 진입 경로 → 화면 요소(위→아래) → 동작 → 입력 검증 → 빈·오류 상태 → 관련 FR** 순서로 적습니다.

### S01 분야 선택 — `01_분야선택.html`

**목적**: 뉴스를 모을 분야 3개(1순위 큰 분야, 깊은 분야, 2순위 큰 분야)를 고른다. (✅ FR-01-1)

**진입 경로**
- 앱 첫 실행 (저장된 분야가 없을 때) ✅ FR-01-1
- 저장 전에 앱을 닫았다가 다시 실행 ✅ FR-01-1
- S02의 나의 관심 분야·추천 뉴스 탭 안내의 "분야 고르기" 버튼 ✅ FR-01-7
- S04 설정의 "관심 분야 다시 고르기" (다시 고르기 모드) ✅ FR-01-8

**화면 요소 (위 → 아래)**

|:---:|---|---|:---:|
| 1 | 상단 바 | 왼쪽: "이전" 버튼(2·3단계에서만 보임). 다시 고르기 모드에서는 1단계 왼쪽에 "취소(✕)" | 이전 ✅ / 취소 버튼 모양·위치 ✅ (Q6) |
