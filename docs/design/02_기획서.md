## 1. 배경·목적

### 1-1. 한 줄 요약

> **AI가 내가 흥미 있어 할 뉴스 여러 개를 하나로 묶고, "눌러보고 싶은 한 문장"을 알림으로 먼저 보내주는 상식 뉴스 앱.**

### 1-2. 문제 (왜 필요한가)

상식을 늘리려고 뉴스를 보고 싶지만, 실제로는 **직접 찾아보지 않게 됩니다.** 찾아봐도 아래 문제 때문에 금방 그만둡니다.

| # | 문제 | 설명 | 중요도 |
|---|---|---|:---:|
| P1 | 재미가 없다 | 관심 없는 기사가 먼저 보인다. "과학", "컴퓨터"처럼 분야를 정해도 범위가 너무 넓다. | ★★★ (가장 큼) |
| P2 | 내용이 부실하고 흩어져 있다 | 기사 하나만 보면 내용이 적거나 결론이 없다. 전체 그림을 보려면 여러 기사를 찾아 다녀야 한다. (제목이 자극적인 것이 아니라 *정보의 양과 완결성* 부족이 문제) | ★★★ |
| P3 | 깊이 들어가면 너무 어렵다 | 더 찾아보면 내 수준보다 지나치게 전문적인 글이 나온다. | ★★ |
| P4 | 찾아보는 행동 자체를 안 한다 | 검색하면 해결되지만, 귀찮아서 결국 안 하게 된다. | ★★★ |

**핵심 통찰**: 사용자가 뉴스를 *찾으러 가는* 구조로는 실패한다. 뉴스가 **먼저 찾아와야** 하고, 첫 문장이 **재미있어야** 한다.

### 1-3. 목적

| # | 목적 | 해결하는 문제 |
|---|---|---|
| G1 | 내가 고른 분야(큰 분야 + 깊은 분야)에 맞춘 뉴스를 보여준다 | P1 |
| G2 | 같은 사건을 다룬 여러 기사를 **한 편의 종합 기사**로 정리해, 풍부하고 결론까지 있는 정보를 준다 | P2 |
| G3 | 종합 기사 속 어려운 단어에 해설을 붙인다 | P3 |
| G4 | 흥미를 끄는 한 줄을 **알림으로 먼저** 보내, 찾아가지 않아도 뉴스가 보이게 한다 | P4, P1 |

### 1-4. 확인할 가설 (MVP)

> **"흥미로운 한 문장을 먼저 보여주면, 사람들이 뉴스를 실제로 눌러 읽는다."**

### 1-5. 결정된 원칙 ✅

| 우선순위 | 원칙 |
|:---:|---|
| 1 | 본체는 **여러 기사를 모아 풍부하고 결론까지 있는 정보**를 주는 것 (정보 제공이 본체) |
| 2 | 어그로 한 줄(후킹 문장)은 사람을 끌어오는 **부가 기능** — 자극적인 표현·유행어 허용 |
| 3 | 어그로 한 줄의 **과장은 허용**한다. 대신 화면에 **안내 문구**를 둔다 |

- 과장을 허용하는 이유: 사용자는 한 줄을 "사실"이 아니라 "**미끼**"로 받아들인다. 눌렀을 때 약속보다 더 많은 정보(종합 기사)가 나오므로 낚시성 제목과 다르다. 한 줄만 보고 넘기는 경우까지 책임지도록 설계하지 않는다.

### 1-6. 차별점

> 포털은 "기사 목록"을 주고, 요약 뉴스레터는 "남이 고른 뉴스"를 준다.
> 이 서비스는 **"내 취향에 맞춘 사건 하나를, 여러 기사로 모아, 내 수준으로" 준다.**

## 2. 대상·사용자

| 구분 | 대상 | 비고 |
|---|---|---|
| 1차 사용자 | **나 자신** — 상식이 부족하다고 느끼지만, 뉴스를 찾아보는 습관이 없는 사람 | MVP는 1명 사용 기준 (회원 기능 없음) |
| 확장 대상 (가정) | 같은 고민을 가진 대학생·사회초년생 | 가정일 뿐, MVP 범위 아님 |

**사용자 특징**
- 관심 분야(예: 컴퓨터)가 있지만 **전문가 수준은 아니다.**
- 스몰토크(가벼운 대화)에서 뒤처지고 싶지 않다.

**사용 흐름**

```
[1] 처음 시작할 때 관심 분야를 단계별로 고른다
        ↓
[2] (서버) AI가 페이지별 뉴스를 모아 같은 사건끼리 묶고, 종합 기사 + 어그로 한 줄을 만든다
        ↓
[3] 휴대폰에 알림이 온다 — 알림에 어그로 한 줄 표시 (찾아가지 않아도 보임)
        ↓
[4] 흥미가 생기면 알림을 누른다
        ↓
[5] 여러 기사를 합친 종합 기사를 읽는다 (어려운 단어는 탭하면 해설)
        ↓
[6] 출처(원문 기사 링크)를 확인할 수 있다
```

#### FR별 확정 세부 사항

**FR-01 카테고리별 맞춤 기사 모으기**

| 페이지 | 채우는 기준 | 뉴스 출처 |
|---|---|---|
| 오늘의 화제 | 그때그때의 **시사**. 모르면 "조금 무식하다" 소리를 들을 수 있고, 직장 등에서 스몰토크에 낄 수 있을 정도의 뉴스 (관심 분야와 무관) | 구글 뉴스 "주요 뉴스" RSS |
| 나의 관심 분야 | 1순위 큰 분야 + 그 안의 깊은 분야 | 네이버 뉴스 검색 API (관심 키워드로 검색) |
| 추천 뉴스 | 2순위 큰 분야 (깊은 분야 선택 없음). 탭 맨 아래에 **다른 분야 한 줄**(고르지 않은 분야마다 1개, 어그로 한 줄 + 누르면 원문 기사)을 작게 덧붙임 (v1.4) | 네이버 뉴스 검색 API (관심 키워드로 검색) |

처음 시작할 때 분야 선택 순서:

```
① 가장 좋아하는 큰 분야 고르기     (예: 자연, 경제, 과학 …)
        ↓
② 그 분야 안에서 깊은 분야 고르기   (예: 과학 → 우주)
        ↓
③ 두 번째로 관심 있는 큰 분야 고르기 (깊은 분야는 고르지 않음)
```

**분야 목록** ✅ (사용자 위임으로 작성 — 네이버·다음 뉴스의 섹션 분류를 참고하고, 사용자가 예로 든 "자연", "과학"을 별도 분야로 둠)

- 큰 분야 10개, 깊은 분야는 큰 분야마다 4~6개.
- "검색 키워드"는 나의 관심 분야·추천 뉴스 페이지에서 네이버 뉴스 검색 API에 넣을 검색어입니다.
- 추천 뉴스(2순위 큰 분야)는 깊은 분야를 고르지 않으므로, 그 큰 분야의 깊은 분야 키워드를 **골고루 섞어** 검색합니다.

> 키워드는 시작용 초안입니다. 실제로 검색해 보고 결과가 엉뚱하면 키워드를 고칩니다.

**FR-02 종합 기사**
- 본문은 **복사가 아니라 AI가 새로 쓴 정리 + 원문 링크** 형태로 만든다.
- 기사 본문은 원문 링크를 열어 **본문 추출 라이브러리**(예: 파이썬 `trafilatura`)로 글자만 뽑는다. **추출에 실패하면 요약(검색 결과의 몇 줄 요약)만으로** 작성한다.
- 화면에는 항상 **출처 기사 링크**를 단다.
- 어려운 단어: 밑줄 표시 → 탭하면 해설.

**FR-03 어그로 한 줄**
- 문장 규칙: 극단적인 단어 사용(예: "내일", "지금", "죽음", "멸망") + 유행어·친근한 말투(너무 자극적이지 않은 선)
- 예시: 자극적인 기사 제목 **10~20개**를 지시문에 함께 넣는다.
- 안내 문구 (예시):
  > "오늘의 한 문장"은 흥미를 위해 사실을 과장할 수 있어요. 정확한 내용은 꼭 기사 본문에서 확인해 주세요.

**FR-04 알림**
- 안드로이드 알림만 사용. 홈화면 위젯·잠금화면 전용 화면은 쓰지 않는다.
- **알림 시각 ✅: 하루 3번 — 아침 7시, 점심 12시, 저녁 19시**

```

어그로 한 줄 ──담겨서──▶ 알림 ──누르면──▶ 종합 기사
```

## 5. 시스템 구성 개요

### 5-1. 확정된 구성 원칙 ✅

- **플랫폼: 안드로이드 앱** (Windows에서 개발 가능, 설치 파일로 바로 설치, 비용 없음)
- **AI 작업(뉴스 수집·묶기·정리·문장 생성)은 서버 쪽에서** 하고, **앱은 결과를 보여주기만** 한다. → 나중에 아이폰·웹을 추가할 때 화면만 새로 만들면 된다.
- 뉴스 출처는 아래 조합으로 확정:

| 대상 | 출처 | 가입·키 | 받는 것 | 선택 이유 |
|---|---|---|---|---|
| 오늘의 화제 | 구글 뉴스 "주요 뉴스" RSS | 필요 없음 | 제목, 링크, 언론사, 날짜 | 같은 사건의 다른 언론사 기사 목록이 **이미 묶여서** 와서 기사 묶기 작업이 크게 줄어듦 |
| 나의 관심 분야 / 추천 뉴스 | 네이버 뉴스 검색 API | 무료 가입 후 키 발급 | 제목, 요약 몇 줄, 원문 링크, 날짜 | 키워드 검색이 쉽고 원문 링크를 바로 줌 |
| 종합 기사 본문 | 원문 링크 → 본문 추출 라이브러리 | - | 기사 본문 글자 | 위 출처들은 본문 전체를 주지 않음. 실패 시 요약만 사용 |

### 5-2. 구성 개요도

```
 ┌──────────────── 서버 쪽 (AI 처리) ────────────────┐
 │                                                    │
 │  [구글 뉴스 RSS]   [네이버 뉴스 검색 API]          │
 │        └──────┬──────────┘                         │
 │               ▼                                    │
 │      ① 기사 모으기 (FR-01)                         │
 │               ▼                                    │
 │      ② 원문 링크에서 본문 추출 (실패 시 요약만)    │
 │               ▼                                    │
 │      ③ AI: 종합 기사 + 어려운 단어 해설 (FR-02)    │
 │               ▼                                    │
 │      ④ AI: 어그로 한 줄 (FR-03)                    │
 │               ▼                                    │
 │      ⑤ 결과 저장  ──────────┐                      │
 └─────────────────────────────┼──────────────────────┘
                               ▼
 ┌──────────── 안드로이드 앱 (보여주기만) ────────────┐
 │  - 처음 시작: 단계별 분야 선택 (FR-01)              │
 │  - 알림: 어그로 한 줄 + 누르면 종합 기사 (FR-04)    │
 │  - 페이지 3개: 오늘의 화제 / 나의 관심 분야 / 추천  │
 │  - 종합 기사: 출처 링크, 단어 탭 해설, 안내 문구    │
 └─────────────────────────────────────────────────────┘
```

### 5-3. 서버 방식 ✅ (사용자 위임으로 결정)

**원칙: 서버 컴퓨터를 직접 빌리거나 켜 두지 않는다.** 모두 무료 서비스로 해결한다.

| 역할 | 사용 도구 | 설명 |
|---|---|---|
| 정해진 시간에 실행 | **GitHub Actions 예약 실행** (코드 저장소 사이트 GitHub의 무료 자동 실행 기능) | 하루 3번 **6:30 · 11:30 · 18:30**에 파이썬 스크립트를 실행. 예약 실행은 몇 분씩 늦어질 수 있어 알림 30분 전에 돌린다 |
| 뉴스 처리 | **파이썬 스크립트** | ① 기사 모으기 → ② 본문 추출 → ③ AI로 종합 기사·단어 해설·어그로 한 줄 생성 |
| 결과 저장 | **Firebase Firestore** (구글의 무료 앱 데이터 저장 서비스) | 스크립트가 결과를 올리고, 앱은 읽기만 한다 |
| 사용자 분야 선택 저장 | Firestore | 앱이 고른 분야를 저장 → 스크립트가 읽어서 **고른 분야만** 처리 (AI 비용 절약) |
| 알림 | **앱이 스스로 예약하는 알림** | 앱이 7시·12시·19시에 최신 어그로 한 줄을 읽어 알림을 띄운다. 서버에서 알림을 보내는 기능(푸시 서버)은 쓰지 않는다 |

- 필요한 계정: GitHub, 구글(Firebase·Gemini API), 네이버 개발자 센터. 모두 무료.
- 세부 기술 선택과 이유는 이후 [아키텍처·ADR](08_아키텍처_ADR.md)(🔴 미작성)에 기록합니다.

### 5-4. 사용할 AI 모델 ✅

**결정: 구글 Gemini API 무료 요금제 — Flash-Lite 모델** (비용 0원)

| 항목 | 내용 |
|---|---|
| 가입 | Google AI Studio에서 구글 계정으로 키 발급 (카드 등록 없음) |
| 사용량 | 하루 약 33번 호출 (한 번 실행에 기사 묶음 11개 × 하루 3번) |
| 한도 | 공식 문서에 무료 한도 숫자가 없음 → **가입 후 AI Studio 화면에서 실제 한도 확인**. 외부 자료 기준 Flash-Lite는 하루 약 500회로 넉넉함 (Flash는 약 20회로 부족할 수 있음) |
| 설계 원칙 | **AI 부분은 쉽게 갈아끼울 수 있게** 만든다. 한도가 줄거나 품질이 아쉬우면 다른 AI(다른 Gemini 모델, Claude API 등)로 바꾼다 |

- 주의: 무료 요금제는 **보낸 내용이 구글 제품 개선에 쓰인다.** 공개된 뉴스 기사만 보내므로 문제 없음. 개인정보는 AI에 보내지 않는다.
- 무료 한도는 자주 바뀔 수 있다.

> 기술 선택과 이유는 이후 [아키텍처·ADR](08_아키텍처_ADR.md)(🔴 미작성)에서 확정·기록합니다.

## 7. 가정·제약

### 7-1. 가정

| # | 가정 |
|---|---|
| A1 | 사용자는 어그로 한 줄을 "사실"이 아니라 "미끼"로 받아들인다. (기사 제목의 "멸망", "임박" 같은 과장을 그대로 믿는 사람이 거의 없는 것과 같다) |
| A2 | 알림으로 흥미로운 한 줄을 먼저 보여주면 사용자가 실제로 눌러 읽는다. (MVP로 확인할 가설) |
| A3 | 대학생·사회초년생도 같은 고민을 가지고 있다. (확장 대상, 검증 안 됨) |
| A4 | 대학 과제·비공개 시연 범위에서는 저작권 부담이 적다. |

### 7-2. 제약

| # | 제약 | 대응 (확정) |
|---|---|---|
| C1 | 대학교 과제 프로젝트 — 상용화가 아니며 **최대한 쉬운 구현**이 목표 | 기능을 4개로 최소화, 쉬운 출처 조합 선택 |
| C2 | 언론사 기사 본문에는 **저작권**이 있다 | 본문 복사가 아니라 AI가 새로 쓴 정리 + 원문 링크. 출처 링크 항상 표시. **공개 배포하지 않음** |
| C3 | 구글 뉴스 RSS·네이버 API 모두 **본문 전체를 주지 않는다** | 원문 링크에서 본문 추출, 실패 시 요약만 사용 |
| C4 | 구글 뉴스 링크는 구글을 한 번 거치는 주소라 **원문 주소를 바로 알기 어렵다** | (해결 방법은 이후 설계에서 정함) |
| C5 | 네이버 뉴스 검색 API는 **검색어 기반**이며 하루 25,000회 무료. 인기 뉴스 목록 기능은 없음 | 오늘의 화제는 구글 뉴스 RSS, 관심 분야·추천은 네이버 사용 |
| C6 | 포털·언론사는 **기사별 클릭수를 공개하지 않는다** | 클릭수 분석 제외, 규칙 + 예시 지시문 방식 사용 |
| C7 | 안드로이드는 기기·버전마다 동작이 다르고, 배터리 정책 때문에 자동 갱신이 막히기도 한다 | 위젯 없이 알림만 사용, AI 처리는 서버 쪽 |
| C8 | 실명 기자 평가는 명예훼손 위험 | 기자 평가 기능 삭제 |
